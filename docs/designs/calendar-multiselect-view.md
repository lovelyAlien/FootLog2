## Problem Statement
지금은 하루 단위(오늘 뷰 / 캘린더 과거 날짜 뷰)로만 기록을 볼 수 있다. 사용자가 하루보다 넓은 범위(며칠, 한 주, 한 달, 또는 주말만 같은 불연속 패턴)로 기록을 모아 보고 싶어 했으나, 화면을 구체적으로 어떻게 구성해야 할지 스스로 아이디어가 떠오르지 않아 office-hours로 가져옴.

## Premises
1. 이 기능(넓은 기간 기록 보기)은 문서상 이미 "주간 반복 패턴 분석"으로 정의돼 Phase 2, 웨지 밖으로 명시적 연기된 항목과 사실상 동일 — 지금 스코프에 넣으면 그 결정을 뒤집는 것. 사용자 확인: **뒤집지 않는다** — 이 세션은 화면 아이디어만 스케치하고, 실제 스코프 편입은 Phase 1 핵심 루프(체크인) 실사용 검증(1~2주) 후로 유예.
2. Phase 1(알림→체크인→오늘 뷰)은 세션 시점 기준 아직 코드 없음 — 구현·실사용 검증 모두 시작 전.
3. 완료율/진행률 숫자·배지 노출 금지(CRITICAL, DESIGN.md) 원칙은 이 화면에도 그대로 적용 — 선택 상태 표시에 개수(예: "3일 선택됨")를 쓰지 않고 실제 날짜/패턴명으로 표시.

## Approaches Considered
### Approach 1: 달력 그리드, 지도 없는 별도 화면 (반려)
캘린더 아이콘의 날짜 피커를 월 그리드로 확장하고 "이번 주" 리본으로 주간을 별도 화면 없이 흡수하려 함. 지도가 빠져 "지도가 1차 시각적 앵커"라는 기존 확정 원칙과 어긋나 반려.

### Approach 2: 지도 오버레이, 월간 핀 전체 (요소만 재활용)
지도를 유지하며 한 달치 핀을 전부 겹쳐 표시. 매시간 알림 기준 한 달 최대 500~700개 체크인이 겹칠 수 있어 가독성 문제가 지적됨. 지도+핀 조합 자체는 이후 버전에서 재사용, 겹침 문제는 Phase 1 실사용 후 실측해 필요하면 대응하기로 유예(지금 미리 클러스터링을 설계하지 않음).

### Approach 3: 일/주/월 세그먼트 토글, 월은 밀도 히트맵 (반려)
지도 위 세그먼트 컨트롤로 기간을 전환하고, 월 화면만 개별 핀 대신 밀도 히트맵 + "새로 가본 곳" 마커로 바꿔 겹침 문제를 회피하려 함. 사용자가 명시적으로 반려: 주 단위 구분 자체가 불필요하고, 월 화면도 히트맵이 아니라 핀으로 보고 싶다고 확인.

### Approach 4: 일/월 두 세그먼트, 월은 핀 그대로 (반려)
Approach 3에서 주 세그먼트만 제거하고 월은 핀으로 되돌림. 사용자가 한 단계 더 근본적인 대안을 직접 제시: "일 단위도 빼고, 달력에서 날짜를 선택한 것들을 보여주면 어떨까" — 고정된 기간 단위 자체를 없애는 방향으로 대체됨.

## Recommended Approach
**Approach 5: 달력 자유 선택 (지도 + 바텀시트, 멀티셀렉트 달력)**

오늘 뷰의 지도+바텀시트 골격을 그대로 재사용하되, 시트 안 콘텐츠를 "오늘 체크인 리스트"에서 "멀티셀렉트 가능한 월 달력"으로 교체한다. 날짜를 자유롭게 탭해서 고르면 — 하루만, 연속된 며칠, 이번 달 전체, 주말만 같은 불연속 패턴까지 — 전부 같은 인터랙션 하나로 처리되고, 선택된 날짜들의 체크인만 지도에 핀으로 모아 보여준다. 궤적선은 선택이 연속된 구간일 때만 그려 실제로 하지 않은 이동처럼 보이는 것을 피한다.

**퀵 필터 칩 제거(2026-08-23 재확인 세션):** 처음엔 오늘/이번 주/이번 달 전체/주말만 흔한 패턴을 한 번에 고르는 퀵 필터 칩을 뒀으나, 화면 요소를 줄이는 쪽으로 재검토해 제거 — 전부 달력에서 직접 탭으로 고른다. 트레이드오프: "이번 달 전체"는 30번, "주말만"은 8~10번 탭이 필요해짐. 이 화면 자체의 실사용 빈도가 아직 검증 전(Assignment 참고)이라, 지금은 뺀 채로 시작하고 실제로 불편하면 다시 추가하기로 함.

**드래그 멀티셀렉트 추가(2026-08-23 재확인 세션):** iOS 사진 앱의 사진 다중 선택 제스처를 차용 — 짧은 탭은 그 날짜 하나만 토글(기존과 동일), 누른 채로 움직이면 범위 선택이 시작됨.
- **경로 추적이 아니라 인덱스 범위 선택**(프로토타입 검증 중 수정, 2026-08-23): 처음엔 "손가락이 화면에서 실제로 지나간 칸"을 선택하는 방식으로 구현했으나 잘못된 모델임이 확인됨 — 손가락이 1일에서 8일로 순간적으로 건너뛰어도(중간을 화면상 거치지 않아도), **달력의 날짜 순서(그리드를 왼쪽 위부터 오른쪽 아래로 읽는 순서)상 시작 날짜와 현재 날짜 사이에 있는 모든 날짜**가 선택되어야 함 — 사진 앱이 정확히 이 방식(사진 번호 순서로 범위를 채움, 화면 경로 무관). 1일과 8일처럼 같은 열(토요일) 바로 아래위에 있어 화면상 경로로는 중간 날짜를 하나도 지나지 않는 경우에도 인덱스 범위이므로 전부 선택됨.
- **선택/해제 모드는 드래그 시작 칸이 정함**(사진 앱과 동일 원리): 미선택 칸에서 드래그를 시작하면 범위 안 날짜를 전부 "선택"으로, 이미 선택된 칸에서 시작하면 범위 안 날짜를 전부 "해제"로 바꿈. 범위는 손가락이 움직일 때마다 다시 계산되며, 범위 밖으로 벗어난 날짜는 드래그 시작 전 상태로 되돌아감(사진 앱처럼 미리보기 성격 — 손을 뗄 때 그 순간의 범위만 최종 반영).
- **불연속 패턴(주말만 등)엔 한계 있음** — 토요일과 일요일이 그리드에서 이웃하지 않아(한 주 끝 → 다음 주 시작) 한 번의 직선 드래그로 훑을 수 없음. 이 경우는 여전히 요일마다 개별 탭 필요 — 다만 그마저도 "이번 달 전체" 같은 최악의 케이스보다는 부담이 훨씬 적어 칩 제거의 순비용이 작아짐.
- 드래그 중 지도가 실시간으로 따라 바뀌는지, 손 뗀 뒤 반영되는지는 Open Questions 참고 — 후자가 구현 단순하고 셀 수십 개를 훑는 동안 지도가 계속 다시 그려지면 산만할 수 있어 후자 쪽에 무게가 실림.

**T10과의 관계 (확정, 2026-08-23 재확인 세션 → 같은 날 `/plan-design-review` 진행 중 진입점 통합으로 갱신):** 날짜 하나만 고르면 이 화면이 지금의 "캘린더 과거 날짜 뷰"(T10)와 결과가 동일해진다는 관찰에서, T10을 이 화면에 흡수하는 안도 검토했으나 **T10은 별도로 유지, 스크러버도 그대로 유지하기로 확정**. 이유: 겹치는 시나리오는 "날짜 하나만 골라 그날을 보는" 경우뿐이고, T10엔 이미 승인·크로스모델 리뷰까지 통과한 날짜 스크러버(인접 날짜를 하루씩 훑는 기능)가 딸려있는데 이건 "T10이 전용 단일 날짜 화면"이라는 전제 위에서 설계된 것 — 이 새 화면(멀티셀렉트 달력)과는 인터랙션 성격이 달라(빠른 점프 vs 여러 날 비교) 스크러버를 옮겨 붙이면 오히려 헷갈림.

**체크인 버튼 미노출 (2026-08-23 `/plan-design-review` — CRITICAL gap 해소):** 이 화면은 오늘 뷰의 지도+바텀시트 골격을 재사용하지만, T10(캘린더 과거 날짜 뷰)과 동일한 원칙으로 **체크인 버튼을 노출하지 않는다** — 과거 날짜를 보는 중에 체크인하면 화면에 보이는 날짜가 아니라 오늘 날짜로 기록되어 화면과 어긋나기 때문. 골격 재사용이 "시트 콘텐츠만 교체"라는 문구 때문에 지도 레이어의 체크인 버튼이 암묵적으로 남아있는 것처럼 읽힐 수 있어 명시적으로 못박음.

**진입점 확정 (2026-08-23, 아래 Open Questions 첫 항목 해소 — 하단 탭바 도입에 따라 T10과 한 진입 동작 안에서 제스처로 갈림, `footlog-product-design.md` "네비게이션" 항목 참고):** 별도 아이콘이나 모드 토글 없이, **캘린더 탭 홈(월 그리드, 아직 아무 것도 선택 안 한 초기 상태)에서 제스처가 목적지를 정함** — 드래그 없는 **단순 탭 1번**은 곧바로 T10으로 push(기존 "캘린더 아이콘 → 팝업 모달 → 즉시 이동" 체감과 동일, 스크러버 포함 화면 그대로 유지). **누른 채 드래그**하면 이 화면(Approach 5, 지도+시트 통합 화면)으로 그 자리에서 승격되어 지도가 실시간으로 채워지고, 승격된 뒤에는 위에 이미 스펙된 "탭 = 개별 토글" 동작이 그 화면 안에서 정상 작동(추가 탭이 T10으로 다시 튀지 않음 — 승격은 한 세션 동안 한 번만 일어남). 결과적으로 진입점은 캘린더 탭 하나뿐이고, 목적 화면(T10 vs 이 화면)은 첫 제스처가 결정.

## Visual Design Decisions
- 선택된 날짜: 셀 전체가 아니라 **숫자 둘레에만** `#D8DDC9`(accent-soft) 채운 원(지름 30pt) — 테두리 링이 아니라 배경이 채워진 원. 탭으로 토글(선택 ↔ 해제).
  - **결정 경과(2026-08-23, office-hours 재확인 세션):** 처음엔 숫자 둘레에 테두리만 두른 홀로우 링으로 시각화(승인된 mockup variant A가 이 형태)했으나, 연속된 날짜 여러 개(예: 한 주 7일)를 함께 선택했을 때 테두리끼리 시각적으로 뭉개져 "어디부터 어디까지 선택됐는지"가 한눈에 안 들어오는 문제 발견. 같은 크기로 배경을 채운 원과 나란히 비교한 결과, 채운 원이 다중 선택 시 훨씬 빠르게 읽혀 채택. **variant A mockup 이미지 자체는 홀로우 링 상태로 남아있으니, 구현 시 이 문서 스펙(채운 원)을 따를 것 — 스크린샷을 그대로 베끼지 말 것.**
- 미선택 + 기록 있음: `#79786F`(text-muted). 미선택 + 기록 없음: `#A7A49A`(text-faint). 오늘: accent 밑줄로 표시해 선택 표시(원)와 시각적으로 구분 — 원과 밑줄은 서로 다른 위치(숫자 배경 vs 숫자 아래)라 동시에 있어도 겹치지 않음.
- 선택 상태 라벨은 개수가 아니라 실제 날짜/구간/패턴명으로 표시 — 예: "8월 17일 – 19일, 22일", "주말만 · 8월" (Premise 3, CRITICAL 원칙 준수).
- 궤적선 예시: 17·18·19일(연속) + 22일(낱개)을 함께 선택하면, 17→18→19 사이에만 궤적선이 그려지고 22일 핀은 선 없이 단독 표시(19일과 22일 사이는 연속이 아니므로 잇지 않음).
- 목업: `~/.gstack/projects/FootLog2/designs/calendar-multiselect-20260823/variant-A.png`(승인된 화면 전체 구도 — 지도 edge-to-edge, 워드마크/헤더 없음, 요일별 색상 구분 없음; 단 이미지 속 날짜 선택 표시는 홀로우 링이고 퀵 필터 칩 5개가 남아있는데, 위에서 설명한 대로 최종 스펙은 채운 원 + 퀵 필터 칩 없음이므로 두 군데 모두 스크린샷을 그대로 베끼지 말 것).
- 인터랙션 프로토타입(실제 동작하는 HTML, 이미지 아님): 드래그 범위 선택의 최종 로직(인덱스 범위, 시작 칸이 모드 결정, 범위 밖은 드래그 전 상태로 복원)을 직접 눌러서 검증함 — 위 설명이 실제로 그렇게 동작하는지 이 문서만으로 판단이 안 서면 재구현해서 확인할 것.
