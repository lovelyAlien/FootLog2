## Problem Statement
체크인만으로는 원래 전제 #1("의식적으로 멈춰서 알아차리는 행위")이 완성되지 않는다는 게 이번 세션에서 확인됨 — 하루 끝에 오늘 기록을 돌아보고 짧게 정리하는 행위가 있어야 체크인이 실제로 의미를 갖는다. 전체 제품 Problem Statement는 부모 문서 참고.

## Premises
1. **회고 쓰기는 확장 기능이 아니라 핵심 루프의 일부다.** 왜: 창업자가 직접 확인 — "회고 없으면 체크인 자체가 의미 없다". 부모 문서에서 "NOT in scope, 2단계"로 명시 분류됐던 결정이 이 답변으로 뒤집힘.
2. 하루 마무리 화면의 지도는 오늘 뷰의 지도+궤적선 **정적 렌더링만** 재사용 — 오늘 하루치만, 다중 날짜 겹침 없음. **플로팅 체크인 버튼, 3단계 스냅 바텀시트 등 오늘 뷰의 인터랙티브 요소는 가져오지 않음**(이 화면은 입력이 아니라 회고용이므로) — 하루 마무리 화면 자체의 레이아웃은 위 Visual Design Decisions 참고.
3. **회고 입력은 2칸 — 하나는 고정 프롬프트, 하나는 자유 회고(2026-08-23 수정).** 첫 칸은 고정 질문 "새로 가본 곳이 있었나요?"(로테이션 없음, 전제 #6 유지). 둘째 칸은 원래 고정 질문("오늘 하루를 한 문장으로 표현한다면?")이었으나, 한 문장으로 제한하지 않고 **길이·형식 제약 없는 자유 회고**로 변경 — 라벨/placeholder는 질문형이 아니라 짧은 초대 문구 "오늘에 대해"(체크인 메모 placeholder와 같은 톤, 강요하는 질문형 아님). 후보로 제시됐던 "오늘 반복된 곳이 있었나요?"는 여전히 채택 안 함.
4. **"오늘 돌아보기" 알림 추가** — 기존 체크인 알림(매시간/3시간마다 반복 트리거)과 별개, 하루 1회 고정 시각 트리거, 고정 문구 하나. **1단계에서는 시각 자체는 하드코딩(예: 21:00), 사용자가 조정 가능한 건 켜기/끄기 토글뿐**(시각 변경 UI는 스코프 밖) — Cross-Model Perspective에서 Codex가 지적한 리스크(정해진 시각 알림이 자유형 체크인 원칙과 충돌)에 대한 절충안. 이 토글은 기존 설정 화면(햄버거 메뉴)에 세 번째 항목으로 추가 — 부모 문서에서 "알림 빈도, 버전 정보" 2개로 확정했던 설정 화면 구성이 이 문서로 3개로 늘어남. **기본값 확정(2026-08-23 `/plan-design-review`): 기본 켜짐** — Codex가 지적한 리스크(정해진 시각 알림이 자유형 원칙과 충돌)를 인지한 상태에서 창업자가 직접 선택. 회고가 "확장 기능이 아니라 핵심 루프의 일부"(전제 1)라는 이 문서의 핵심 전제와 일관되게, 기본으로 노출해 발견 가능성을 우선함 — 1~2주 실사용 검증에서 이 알림이 실제로 무시되는지는 아래 Success Criteria에서 그대로 관찰.
5. 진입점은 수동(오늘 뷰 버튼)과 알림 둘 다 지원. **수동 진입 위치 확정(2026-08-23 `/plan-eng-review`, Codex 지적 — 위치 미정 gap 해소):** 오늘 뷰 바텀시트의 체크인 리스트 맨 위에 "오늘 돌아보기" 행을 상시 노출(accent-soft 배경으로 리스트 행과 살짝 구분). 체크인이 0건이어도 항상 보임 — 회고는 체크인 여부와 무관하게 언제든 쓸 수 있어야 하므로. 탭하면 알림과 동일한 모달이 열림 — 두 진입 경로(수동/알림) 모두 같은 화면으로 귀결되어 알림을 놓쳐도 회고 작성 자체는 막히지 않음. 새 아이콘·헤더 자리 불필요, 새로 만드는 코드 없음(기존 리스트 렌더링 로직에 항목 하나 추가). **알림-회고 날짜 귀속 확정(2026-08-23 `/plan-eng-review`, Codex 지적 — 자정 넘어 탭할 때의 모호함 해소):** 알림 페이로드에 "이 알림이 어느 날짜 회고인지"를 예약 시각 기준으로 박아둠 — 자정을 넘겨 탭해도 항상 알림이 예약된 그 날짜의 `DailyReflection`이 열림("지금 몇 시인지" 계산 불필요, 알림 자체가 날짜를 들고 있음). **프레젠테이션 방식 확정(2026-08-23 `/plan-eng-review`, Section 1 아키텍처 gap 해소):** 모달로 화면 전체가 아래→위 슬라이드해 하단 탭바까지 통째로 덮음(닫기는 좌상단 ✕, 뒤로가기 화살표 아님) — T10/멀티셀렉트 결과 화면처럼 "탭 스택 안 push"가 아님. 이 화면은 "어디론가 이동"이 아니라 "잠깐 열어서 정리하고 닫는" 포커스 태스크 성격이라 모달이 자연스럽고, 탭바 위 레이어에 아예 존재하지 않게 되어 "탭바를 숨길지" 결정 자체가 불필요해짐(iOS의 "새 일정 추가" 류 모달과 동일 관례). 알림 탭 시에도 탭 스택에 쌓는 대신 그냥 모달로 띄우면 됨.
6. 체크인 0건인 날에도 알림/화면 진입은 동일하게 동작 — 특별 처리 없음(빈 지도/리스트, 프롬프트는 그대로 노출).
7. **저장은 조용한 자동저장** — 별도 "저장" 버튼 없이 텍스트 입력 시 디바운스 후 자동 저장, "저장됨" 같은 완료 문구도 표시하지 않음(전제 #6, 체크인 흐름의 "즉시 저장" 톤과 동일). Codex 제안을 명문화. **디바운스 시간·백그라운드 유실 방지·저장 실패 UI (2026-08-23 `/plan-design-review`에서 추가 — CRITICAL gap 해소):** 성공과 실패가 똑같이 "아무 일도 안 일어남"으로 보이는 조용한 자동저장의 특성상, 실패 경로를 명시하지 않으면 실패가 곧 성공처럼 보인다. 이 앱이 존재하는 이유 자체("수기 일기를 자주 까먹어서 빼먹음")를 생각하면 가장 공들여 쓴 텍스트가 조용히 사라지는 건 직접적인 제품 실패다.
   - **디바운스 5초** — GPS 타임아웃과 동일한 값 재사용(실측 근거 없는 초기 추정치, 1단계 실사용 중 체감으로 조정 가능).
   - **백그라운드 전환 시 강제 flush** — `AppState`가 background로 바뀌는 순간, 디바운스 타이머가 아직 안 끝났어도 즉시 저장을 실행. 타이핑 중 앱이 꺼지거나 전화가 와도 마지막 입력까지 반드시 디스크에 남도록 보장.
   - **모달 닫기(✕/스와이프) 시에도 동일 flush — 확정 (2026-08-24 `/gstack-autoplan` Eng 리뷰, Claude 서브에이전트 지적 — 재발견):** 위 `AppState` 훅은 앱이 백그라운드로 갈 때만 발동하고, 사용자가 ✕ 버튼이나 스와이프로 모달을 그냥 닫는 경로(앱은 계속 포그라운드)는 커버 못 함 — 컴포넌트가 언마운트될 뿐 `AppState`는 안 바뀜. 이 gap은 2026-08-23 Codex 리뷰에서 이미 한 번 지적됐었으나("자동저장이 모달 닫기 시엔 flush 안 됨") 실제 스펙에는 반영되지 않은 채 남아있었음 — "잊어버려서 못 씀"을 막으려는 기능 안에서 똑같은 실패가 재현될 뻔함. **정정:** 모달의 언마운트(unmount) 훅에도 동일한 강제 flush를 건다 — `AppState` 배경전환 flush와 언마운트 flush 둘 다 같은 저장 함수를 호출하는 것으로 충분(중복 로직 아님, 같은 함수의 두 번째 트리거 지점).
   - **저장 실패 시:** 체크인 흐름과 동일한 패턴 재사용 — 조용히 자동 재시도 1회, 그래도 실패하면 입력칸 바로 아래 작고 담담한 인라인 텍스트("저장하지 못했어요")와 "다시 시도" 버튼을 노출(빨간색·경고 아이콘 없음, 전제 #6). 성공 시에는 여전히 아무 표시도 하지 않음 — 실패했을 때만 조용함이 깨짐.
8. **같은 날 재진입 시 항상 편집 가능** — 화면을 다시 열면 그날 이미 쓴 답변이 그대로 로드되고, 언제든 고쳐 쓸 수 있음(부모 문서의 "저장 후 메모/사진 수정, 언제든 가능" 원칙과 동일하게 적용).
9. **체크인 리스트 행에 사진 썸네일 추가 (2026-08-23 추가) — 이 화면에만 적용.** 그 체크인에 사진이 있으면 행 오른쪽에 40×40 정사각 썸네일 노출(행 높이가 썸네일에 맞춰 늘어남), 없으면 텍스트만. **이 결정은 하루 마무리 화면의 리스트에만 적용되고, 오늘 뷰나 캘린더 과거 날짜 뷰의 리스트는 대상이 아님** — 캘린더 과거 날짜 뷰는 별도 세션(`calendar-date-scrubber.md`)에서 이미 "기존 상세화면 재사용, 리스트에 썸네일 없음"으로 명시적으로 결정되어 있고, 이 문서가 그 결정을 뒤집지 않음. 이 화면에서만 썸네일을 넣는 이유: 회고를 쓰기 위해 그날을 "기억해내는" 게 목적이라, 탭해서 상세화면으로 들어가는 한 단계가 오히려 회고 흐름을 끊기 때문 — 반면 캘린더 과거 날짜 뷰는 회고 작성이 목적이 아니라 단순 열람이라 상세화면 재사용으로 충분하다고 판단.

## Cross-Model Perspective
Codex(GPT-5.5, 독립 검토)의 진단: FootLog는 "위치 로거"가 아니라 "일상 기억 재구성 도구"다 — 체크인은 원재료일 뿐, 진짜 가치는 하루 끝에 의미를 만드는 것. 가장 결정적 근거로 "회고 없으면 체크인 자체가 의미 없다"는 답변을 지목(전제 #1과 독립적으로 동일 결론 도달). 전제 #4(새 알림)에 의문 제기 — 이미 알림이 있는 앱에 하루 1회 고정 시각 알림을 추가하면, 어제 세션에서 어렵게 없앤 "정해진 시각에 안 하면 놓친 느낌"이 다시 생길 위험. 검증 방법으로 "1~2주 후 실제로 이 알림을 탭하는지, 무시하게 되는지 관찰"을 제안 → 이 세션에서 "설정에서 끄고 켤 수 있는 토글"로 절충해 반영(전제 #4). 48시간 프로토타입 제안: `DailyReflection` 테이블 하나(하루당 1개, 체크인별 아님) + 오늘 뷰 지도 재사용 + 프롬프트 2칸 + 조용한 자동저장 — AI 요약/프롬프트 로테이션/다중 날짜 지도/패턴 감지/스트릭은 전부 스킵.

## Approaches Considered
### Approach A: 별도 화면 (채택)
"하루 마무리" 전용 화면 신규 라우트. 오늘 뷰 지도+궤적선 재사용, `DailyReflection` 테이블, 수동 진입 버튼 + 토글 가능한 알림. Effort: S, Risk: Low.

### Approach B: 오늘 뷰 인라인 통합 (반려)
새 화면 없이 바텀시트 하단에 회고 프롬프트를 이어붙이는 방식. 코드 표면은 더 작지만, 오늘 뷰의 "지금·기록됨·살아있음"이라는 의미와 "하루를 마무리한다"는 톤이 한 화면에 섞여 흐려질 위험이 있고, 창업자가 명시적으로 요청한 "화면이 있고"와도 결이 다름 — 반려.

### Approach C: 알림 없이 자연 노출 (반려)
알림 자체를 없애고, 다음 앱 실행 시 "어제" 카드로 자연스럽게 노출. Codex가 지적한 리스크를 가장 근본적으로 해소하지만, 이미 합의한 "알림 + 설정 토글" 절충안을 다시 뒤집는 셈이라 반려 — 같은 리스크는 토글로 완화하기로 함.

## Recommended Approach
Approach A. 창업자가 명시적으로 요청한 "화면" 형태와 정확히 일치하고, 이번 세션에서 이미 확정한 스펙을 그대로 구현하면 재작업이 없음.

## Visual Design Decisions
(리뷰 시 지적됨 — 오늘 뷰 수준의 상세 스펙은 아니지만, DESIGN.md 대조에 필요한 최소 골격)
- **레이아웃 순서(위→아래):** 오늘 뷰 지도+궤적선(재사용, 상단) → **"오늘의 흔적"** 섹션(2026-08-23 수정 — 원래 "오늘 체크인 개수/리스트"였으나 개수 표기가 완료율 노출 금지 원칙의 정신을 어겨 제거, 리스트 행만 나열. 0건이면 "아직 기록이 없어요", 사진 있는 행은 오른쪽에 40×40 썸네일) → 프롬프트 2개 입력칸(하단, 기본 노출).
- **타이포:** 프롬프트 라벨(질문 문구)은 시스템 폰트 — "이건 시스템이 묻는다"는 UI 크롬. 답변 텍스트는 세리프 이탤릭(Newsreader) — DESIGN.md 타이포 3계층 원칙상 "내가 직접 쓴 것"이므로 체크인 메모와 동일 규칙 적용.
- **입력칸:** 멀티라인, 필수 표시 없음(체크인 메모 입력칸과 동일 패턴). 첫 칸 placeholder는 프롬프트 문구 자체("새로 가본 곳이 있었나요?"). 둘째 칸(자유 회고) placeholder/라벨은 "오늘에 대해" — 질문형이 아닌 짧은 초대 문구, 길이·형식 제약 없음.
