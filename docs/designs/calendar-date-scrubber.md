## Problem Statement
과거 날짜의 지도+기록을 볼 때, 매번 캘린더 날짜 피커를 열어 날짜를 하나씩 고르는 건 인접한 날짜를 여러 개 훑어보고 싶을 때 번거롭다. 지도 자체에서 손으로 날짜를 스크럽(훑기)하면 그 자리에서 지도와 기록이 실시간으로 바뀌는 게 더 자연스럽다 — 이미 Phase 1 스코프인 T10(캘린더 과거 날짜 뷰)의 인터랙션을 구체화하는 것이라 새 스코프 편입 논쟁은 없음.

## Premises
1. 스크러버는 캘린더 탭의 월 그리드를 대체하지 않고 보조 — 인접한 날짜를 훑어볼 땐 스크러버, 멀리 있는 날짜로 한번에 점프할 땐 캘린더 탭으로 돌아가 그리드에서 직접 탭. **(2026-08-23 `/plan-eng-review` 수정 — 상단 캘린더 아이콘/팝업 모달은 하단 탭바 도입으로 이미 대체됨, 진입 방식은 `footlog-product-design.md` "네비게이션 — 하단 탭바" 항목 참고: 그리드에서 단순 탭 = 즉시 이 화면으로 이동, 드래그 = 멀티셀렉트로 승격.)**
2. 형태: 지도 위에 뜨는 가로 눈금자(iOS 사진 앱 날짜별 뷰와 유사한 패턴) — 원형 다이얼은 검토 후 반려.
3. 눈금자에 체크인 있는 날/없는 날을 밀도(진하기)로만 구분 표시 — 숫자나 배지 없음(부모 문서 전제 #6, "1/4 완료" 배지를 명시적으로 거부했던 원칙과 동일선상).
4. 드래그 중 지도+바텀시트가 실시간으로 따라 바뀜(손 뗄 때만 반영 아님) — "훑어보는" 경험이 핵심이라 즉각 반응해야 함.
5. 스크롤 가능 범위는 첫 체크인 날짜 ~ 오늘까지, 미래로는 넘어갈 수 없음(경계에서 멈춤).
6. 메모/사진은 새 UI 없이 기존 상세화면(부모 문서 T13)을 그대로 재사용.
7. 눈금자는 전체 기록을 한 번에 압축해서 보여주지 않고, 선택된 날짜를 중심으로 한 창(window)만 보여주며 계속 스크롤됨 — iOS 사진 앱과 동일 패턴. 기록이 쌓일수록 눈금이 한없이 얇아지는 문제 회피.
8. **위치: 바텀시트에서 완전히 분리된 독립 플로팅 카드로, 지도 위 고정된 화면 위치에 항상 떠 있음** — 바텀시트의 CLOSED/DRAGGING/OPEN 상태와 무관. 오늘 뷰의 "체크인 버튼은 시트 상태와 무관하게 항상 떠있음" 패턴을 재사용(이 패턴은 이미 부모 문서에서 체크인 버튼으로 검증된 z-index 레이어링 방식: 카드가 바텀시트보다 위 레이어에 고정되어, 시트가 OPEN으로 확장돼도 시트 콘텐츠가 카드 아래로 스크롤될 뿐 카드 자체는 절대 가려지지 않음).
   **정확한 위치·수치(2026-08-23 재수정 — Codex 지적 CRITICAL 오류 해소, `/plan-design-review`):** 카드는 화면 하단에서 132pt 위(시트 CLOSED 피크 높이 100pt + 여백 32pt)에 고정 — 이 값 자체는 유효. 단, z-index 레이어링은 "카드가 안 가려짐"만 보장할 뿐 "지도가 계속 보임"은 보장하지 못한다는 지적을 받아들여, 원래의 절충안(시트 OPEN 최대 높이에 상한을 둬 최소 80pt 지도 스트립만 남기는 방식)을 **폐기**한다 — 스크러버의 핵심 경험(드래그하며 지도가 실제로 바뀌는 걸 보는 것)에 80pt 폭 지도 스트립은 사실상 무의미하다. **대신 스크럽 제스처가 손가락에 닿는 순간 바텀시트를 CLOSED로 즉시 접는다**(기존 220ms 스냅 애니메이션 재사용, 새 모션 불필요) — 이러면 지도가 진짜 화면 대부분을 차지한 뷰포트로 보장된다. 손을 뗀 뒤에도 시트는 CLOSED로 유지되며(스크럽 종료가 자동으로 시트를 다시 열지 않음), 리스트를 보고 싶으면 사용자가 직접 끌어올린다. **헤더 높이 44pt**(표준 iOS 네비게이션 바, 세이프 에어리어 별도)로 명시 — 이전까지 미정이었던 값. 탭바는 이 화면에서 숨김 처리되므로(`footlog-product-design.md` "하단 탭바" 항목 참고) 132pt 계산에 탭바 높이를 반영할 필요 없음.
9. **선택 메커니즘**: 화면 중앙에 고정된 표시선(accent 색)이 있고, 눈금자 쪽이 좌우로 스크롤되어 그 아래를 지나감(iOS 사진 앱과 동일한 "고정 인디케이터 + 움직이는 눈금" 방식 — 눈금이 고정되고 인디케이터가 움직이는 방식 아님).
10. **모멘텀 없음**: 손을 뗀 자리에서 딱 멈춤 — 관성 스크롤(flick 후 미끄러지는 느낌) 없이 드래그 중 1:1 실시간 추적만 함(부모 문서 모션 원칙 "bounce/spring 이징 사용 안 함"과 일관성 유지, iOS 사진 앱의 관성 스크롤과는 의도적으로 다름 — The Assignment는 "훑어보는 느낌" 자체를 참고하는 것이지 관성까지 그대로 가져오는 게 아님). **경계(첫 체크인 날짜/오늘)에서 고무줄 효과(rubber-banding) 없이 즉시 하드 클램프(2026-08-23 명시 추가)** — 네이티브 스크롤 컴포넌트가 기본 제공하는 오버스크롤 바운스를 명시적으로 꺼야 함, 그렇지 않으면 모멘텀 없음 원칙과 모순되는 경계 튕김이 남을 수 있음.
11. **기록이 매우 적을 때(체크인 있는 날이 0~1일)**: 스크러버 자체를 숨김 — 훑어볼 게 없으므로. 캘린더 탭 그리드는 이 경우에도 그대로 동작.
12. **접근성**: 순수 드래그 제스처라 VoiceOver로 직접 조작하기 어려움 — 캘린더 탭의 월 그리드(날짜 탭 이동)가 VoiceOver 사용자의 대체 경로로 항상 유지됨(부모 문서 접근성 원칙과 동일하게, 지도/제스처 조작에는 항상 비-제스처 대체 경로가 있어야 함). **터치 히트 영역 최소 44×44pt(2026-08-23 명시 추가)** — DESIGN.md 접근성 원칙(모든 탭 가능 요소 44px 이상)을 시각적으로 얇은 눈금 자체가 아니라 눈금자 전체 드래그 표면에 적용.
13. **캘린더 탭과의 동기화(2026-08-23 갱신 — 캘린더 아이콘이 하단 탭바로 대체됨, `footlog-product-design.md` "네비게이션" 항목 참고)**: 스크러버는 과거 날짜 화면(캘린더 탭 그리드에서 날짜를 탭한 뒤)에만 나타남 — 오늘 뷰와 캘린더 탭 홈에는 없음. 캘린더 탭 그리드로 돌아가 다른 날짜를 탭하면, 스크러버의 스크롤 창(윈도우)이 그 날짜를 중심으로 다시 맞춰짐.

## Approaches Considered (스크러버 배치)
목업 2개를 직접 비교해서 결정.

### Approach A: 바텀시트 안, 핸들 바로 아래 (반려)
리스트와 시각적으로 강하게 묶이지만, 시트를 OPEN까지 드래그하면 스크러버도 화면 위로 밀려 올라가 지도가 거의 안 보이는 상태에서 조작하게 됨 — "훑으면 지도가 바로 바뀐다"는 핵심 피드백이 하필 가장 적극적으로 훑어볼 상황에서 가장 약해지는 모순.

### Approach B: 지도에 독립 플로팅, 시트와 분리 (채택)
시트 상태와 무관하게 항상 같은 화면 위치에 떠서, 어떤 상태에서도 지도가 함께 보임 — 핵심 피드백 루프가 항상 보장됨. 오늘 뷰의 기존 플로팅 버튼 패턴과 일관성 있어 구현 리스크도 낮음.

## Recommended Approach
Approach B.

## Visual Design Decisions
- 플로팅 카드: `#FBFAF6` 배경, 둥근 모서리(lg, 16px), 옅은 그림자 — 오늘 뷰 바텀시트와 같은 표면 톤.
- 눈금: 체크인 없는 날 = `#DDD8CD`(라인 컬러) 얇고 짧은 선, 있는 날 = `#C7C2B4` 조금 더 길고 진한 선, 선택된 날 = accent(`#7C8660`) 굵고 긴 선.
- 하단 보조 문구(11px, muted): "← 드래그해서 날짜 이동 → · 오늘 이후로는 못 넘어감".
- 모션: 드래그 중 실시간 반응, 별도 스프링/바운스/관성 없음(부모 문서 전제 #6, 모션 원칙 유지 — 위 Premise 10 참고).
