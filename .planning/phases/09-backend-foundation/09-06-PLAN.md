자동 테스트가 커버하지 못하는 유일한 경로 — 개발자가 `./gradlew bootRun` 한 줄로 로컬
PostgreSQL을 자동 기동하고 앱을 띄우는 D-12 경로 — 를 실제로 실행해 확인한다.

먼저 남아 있는 컨테이너를 정리한다(`cd backend && docker compose down -v`). 그다음
`SPRING_PROFILES_ACTIVE=local ./gradlew bootRun`을 백그라운드로 실행하고, 기동이 완료될 때까지
`curl -s -o /dev/null -w '%{http_code}' http://localhost:8080/actuator/health`를 폴링한다(최대
120초). 200을 받으면 `docker ps`로 `postgres` 컨테이너가 실제로 떠 있는지 확인하고, 응답 본문에
`UP`이 포함되는지 확인한다. 확인 후 bootRun 프로세스를 종료하고 `docker compose down -v`로
정리한다.

포트 8080이 이미 점유돼 있으면 기존 프로세스를 죽이지 말고 `--args='--server.port=8081'`로
포트를 바꿔 검증한 뒤 그 사실을 SUMMARY에 남긴다.

이 태스크는 새 파일을 만들지 않는다 — 실행 확인과 로그 기록이 산출물이다. 확인 실패 시
`.claude/skills/systematic-debugging` 절차대로 근본 원인을 먼저 찾고 수정한다.
  </action>
  <verify>
    <automated>cd backend && docker compose down -v ; (SPRING_PROFILES_ACTIVE=local ./gradlew bootRun > /tmp/bootrun.log 2>&1 &) ; for i in $(seq 1 60); do sleep 2; code=$(curl -s -o /tmp/health.json -w '%{http_code}' http://localhost:8080/actuator/health || true); if [ "$code" = "200" ]; then echo "HEALTH_200"; cat /tmp/health.json; docker ps --format '{{.Image}}' | grep -i postgres; break; fi; done; pkill -f "GradleWrapperMain" ; docker compose down -v</automated>
