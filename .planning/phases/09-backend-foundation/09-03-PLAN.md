들어가지 않게 하는 것이 목적이다(T-9-09). `src/`와 `build.gradle.kts`/`settings.gradle.kts`는
빌드에 필요하므로 제외하지 않는다.

작성 후 `docker build`로 이미지를 실제로 만들고, 최종 이미지 안에 원본 소스/Gradle 캐시가

후속 액션) → `./gradlew build --no-daemon`.

job id는 `build`로 둔다(위 검증 명령이 `jobs.build` 경로를 확인한다). 배포 스텝은 넣지 않는다 — D-09가 이번 phase 범위를 로컬+스테이징으로 제한했고 D-10은

있으므로, 이번 phase에서는 필수 체크로 등록하지 않는다.

| Boundary | Description |
|----------|-------------|
| Docker 빌드 컨텍스트 → 런타임 이미지 | 로컬 파일(소스, Gradle 캐시, `.env`)이 배포 아티팩트로 새어나갈 수 있는 경계 |
| GitHub Actions 러너 → 저장소/로그 | CI 로그·아티팩트로 정보가 노출될 수 있는 경계 |
| 컨테이너 프로세스 → 호스트/컨테이너 파일시스템 | 프로세스 권한 경계 |
