## 확정된 `location_source` 매핑 (03-RESEARCH.md Open Questions #1 해소)

| location_source | 트리거 조건 |
|-----------------|-------------|
| `gps_auto` | 권한 granted + `getCurrentPositionAsync`가 5초 내 성공 + 드래그 없음 |
| `gps_low_accuracy_fallback` | 권한 granted + 5초 타임아웃 + `getLastKnownPositionAsync`가 좌표 반환 + 드래그 없음 |
| `manual_no_signal` | 권한 granted + 5초 타임아웃 + OS 캐시도 없음 → 앱 소유 폴백 체인 진입 + 드래그 없음 |
| `manual_denied` | 권한 granted 아님 → `expo-location`을 아예 호출하지 않고 앱 소유 폴백 체인 진입 + 드래그 없음 |
| `gps_dragged` | 위 어느 경로였든 사용자가 핀을 드래그한 모든 경우(원 소스 무관, 드래그 즉시 전이) |

앱 소유 3단계 폴백 체인 순서: (1) 가장 최근 `checkins` row의 lat/lng → (2) 지도가 마지막으로 표시한 좌표(인메모리, 호출부가 전달) → (3) `FALLBACK_COORDINATE`(03-02 창업자 확정값).

    구현: `deps.getCurrentPositionAsync({ accuracy: LOCATION_ACCURACY_BALANCED })`가 만든 프로미스를 지역 변수에 담고, `Promise.race`로 그 프로미스와 `CAPTURE_TIMEOUT_MS` 후 resolve되는 타이머 프로미스를 경합시킨다. **`getCurrentPositionAsync`에 `timeout` 옵션을 절대 넣지 않는다** — 공식 `LocationOptions` 타입에 없는 필드이며 구버전 API에서는 예외를 던진다(03-RESEARCH.md Pitfall 1, GitHub `expo/expo#2226`). 브라우저 Geolocation API와 헷갈리기 쉬운 지점이므로 주석으로 명시한다.

    GPS 프로미스가 이겼으면 `{ kind: 'auto', lat: coords.latitude, lng: coords.longitude, accuracyMeters: coords.accuracy }` 반환. 타임아웃이 이겼거나 GPS 프로미스가 reject된 경우: 버려진 원본 프로미스에 `.catch(() => {})`를 붙여 지연 응답을 흡수하고(이미 타임아웃 처리를 끝낸 뒤의 응답이므로 명시적으로 버리는 것이 의도된 동작임을 주석에 남긴다 — 저장소의 "프로미스를 조용히 삼키지 않는다" 규약의 명시적 예외), `deps.getLastKnownPositionAsync({ maxAge: LAST_KNOWN_MAX_AGE_MS })`를 호출한다. 결과가 있으면 `{ kind: 'timeout_os_cache', ... }`, 없거나 이 호출도 실패하면 `{ kind: 'need_fallback_chain' }`.

    타이머는 반드시 `clearTimeout`으로 정리해 Jest가 열린 핸들로 종료를 지연시키지 않게 한다.
