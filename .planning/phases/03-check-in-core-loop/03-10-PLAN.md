    `src/app/index.tsx`의 `CheckinActionCard` `onConfirm` / `onRetry` 핸들러를 실제 저장 배선으로 채운다.

    **저장 핸들러(`onConfirm`과 `onRetry`가 공유하는 단일 함수)**:
    1. `dispatch({ type: 'TAP_CONFIRM' })`(또는 재시도 시 `TAP_RETRY`)로 `SAVING` 진입.
    2. `state.pin`에서 좌표/소스를 읽어 `NewCheckinParams`를 조립한다: `id`는 `defaultCryptoDeps.randomUUID()`(이미 `SAVE_FAILED` 이후 재시도라면 **같은 id를 재사용한다** — 재시도가 중복 row를 만들지 않도록 첫 `TAP_CONFIRM` 시점에 만든 id를 ref나 리듀서 상태에 보관한다). `timestampUtc`는 `toIsoTimestamp()`, `localDateKey`는 `resolveLocalDateKey(new Date())`, `timezoneAtCapture`는 `resolveTimeZone()`. 타임스탬프는 "확인" 탭 시점에 확정한다(03-RESEARCH.md Pattern 4: 확인 탭이 곧 최종 타임스탬프를 확정하는 시점).
    3. `commitCheckin(db, params)` 호출. `ok: true`면 `dispatch({ type: 'SAVE_SUCCEEDED', id })`, `ok: false`면 `dispatch({ type: 'SAVE_FAILED' })`. 자동 재시도 1회는 `commitCheckin` 내부에 이미 캡슐화돼 있으므로 **화면에 재시도 카운터를 만들지 않는다**(03-RESEARCH.md Pitfall 4). "다시 시도" 버튼은 같은 함수를 다시 호출할 뿐이다.
    4. 예외는 `.catch`로 잡아 `SAVE_FAILED`로 처리하고 `console.error`로 로그를 남긴다.

    `SAVING` 동안 "확인"/"다시 시도" 버튼이 중복 탭되지 않도록 핸들러 진입부에서 `state.phase === 'SAVING'`이면 즉시 리턴하는 가드를 둔다.

    **미저장 이탈 안내**: `state.phase === 'SAVE_FAILED'` 상태에서 사용자가 화면을 벗어나려 할 때(앱이 백그라운드로 전환되거나 카드 바깥을 탭해 플로우를 닫을 때) OS 네이티브 `Alert.alert(CHECKIN_COPY.unsavedExitAlert, undefined, [{ text: CHECKIN_COPY.unsavedExitAlertButton }])`를 **정확히 1회** 노출한다. 이탈 자체를 막지 않는다(정보 제공 목적). Alert를 커스텀 리테마하지 않는다. 중복 노출 방지를 위해 `useRef` 플래그를 쓴다.

    이탈해도 드래프트는 SQLite에 남아 있어 다음 실행 시 복구 제안으로 이어진다(D-05) — 이 사실을 주석에 명시하고, 이탈 시 `deleteDraft`를 호출하지 않는다.
