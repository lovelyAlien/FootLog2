    - `PickPhotoResult = PickedPhoto | null | { error: 'permission_denied' | 'copy_failed' }`

    구현 순서:
    1. `ensurePhotoPermission(source, picker)` — false면 즉시 `{ error: 'permission_denied' }` 반환. picker launch를 호출하지 않는다.
    2. `source === 'camera'`면 `launchCameraAsync({ mediaTypes: ['images'], quality: 1 })`, `'library'`면 `launchImageLibraryAsync({ mediaTypes: ['images'], quality: 1 })`. `mediaTypes: ['images']`를 **반드시 명시**한다 — 미지정 시 기본값이 동영상까지 포함할 수 있어 REQ 스코프(사진만) 밖 파일이 `documentDirectory`에 복사될 위험이 있다(03-RESEARCH.md Assumptions Log A5). deprecated된 `MediaTypeOptions` enum을 쓰지 않는다.

    4. `crypto.randomUUID()`로 UUID를 만들고 `buildPhotoFileName(source, uuid)`로 목적지 파일명을 만든다. **picker가 반환한 `assets[0].uri`나 `assets[0].fileName`을 목적지 파일명으로 절대 쓰지 않는다** — 경로 조작 방어(03-RESEARCH.md Security Domain의 "사진 파일 경로 조작" 완화). 이 규칙을 주석에 명시한다.
    5. `storage.copyIntoDocumentDirectory(assets[0].uri, fileName)`을 `try/catch`로 감싸 실패 시 `{ error: 'copy_failed' }`를 반환한다. 예외를 밖으로 던지지 않되 `console.error`로 로그는 남긴다(프로미스/에러 미삼킴 규약).
    6. 성공 시 `{ uri: <복사된 목적지 uri>, source, fileName }` 반환.

    `cacheDirectory`라는 문자열이 이 파일에 등장하지 않아야 한다(D-02). 문자열 경로 접합(`+`)이나 `expo-file-system/legacy` 참조도 없어야 한다(Pitfall 2) — 경로 조립은 `deps.ts`의 `copyIntoDocumentDirectory`가 `new File(Paths.document, fileName)`으로 이미 처리한다.
