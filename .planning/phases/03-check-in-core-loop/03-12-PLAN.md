    **(A) `src/app/index.tsx`의 크로스페이드 useEffect 교체**

    대상은 `showActionCard` 선언 바로 아래에 있는 `useEffect`(현재 대략 line 194~203, 의존성 배열이 `[isCapturing, buttonContentOpacity]`인 것)다.

    현재 이 effect는 의존성이 `[isCapturing, buttonContentOpacity]`뿐이라, `isCapturing`이 내내 false인 SAVED→IDLE(DISMISS) 전환에서 재실행되지 않는다. 그 사이 알약버튼의 `Animated.View`는 CONFIRM~SAVED 구간 내내 언마운트돼 있었고, 재마운트된 네이티브 뷰가 마지막 `setValue(0)`(크로스페이드 시작값)을 그대로 물려받아 opacity 0으로 렌더된다 — RN의 알려진 native-driver 리마운트 한계(facebook/react-native #28114, #38510, #23712, #23621).

    다음 형태로 바꾼다:

    - 의존성 배열을 정확히 `[showActionCard, isCapturing, buttonContentOpacity]`로 한다. 이것이 gap의 missing 항목 1을 직접 닫는다 — DISMISS로 `showActionCard`가 true→false로 바뀌면 effect가 반드시 재실행된다.
    - effect 본문 맨 앞에서 `showActionCard`가 true면 곧바로 `return`한다(버튼이 아예 마운트돼 있지 않은 구간이라 애니메이션할 대상이 없다). 이 early return 경로는 cleanup을 등록하지 않는다.
    - 그 아래는 기존 동작 그대로: `buttonContentOpacity.setValue(0)` 후 `Animated.timing`(toValue 1, duration `motion.saveStateCrossfadeMs`, `useNativeDriver: true`)을 만들어 `start()`. 단 timing 인스턴스를 지역 const(예: `crossfade`)에 담아 cleanup에서 참조할 수 있게 한다.
    - **cleanup을 새로 반환한다:** `crossfade.stop()`으로 진행 중인 애니메이션을 멈춘 뒤 `buttonContentOpacity.setValue(1)`로 값을 1에 park한다. 이것이 gap의 두 번째 방어선이다 — 어떤 경로로 버튼이 언마운트되든(카드 전환, 캡처 중 CONFIRM 진입, 애니메이션 중간 중단) 네이티브 노드에 남는 마지막 값이 항상 1이므로, 다음 마운트가 0을 물려받는 상황 자체가 생기지 않는다.
    - 훅 규칙을 지킨다: `useEffect` 호출 자체는 조건부로 만들지 말고(early return은 본문 안에서만), 선언 위치도 현재처럼 `showActionCard` 계산 직후에 둔다.

    전환별로 기대되는 결과: IDLE→CAPTURING은 cleanup(stop+park 1) → 본문(setValue 0 + 180ms fade)으로 기존 크로스페이드가 그대로 유지된다. CAPTURING/CONFIRM→카드 표시는 cleanup만 돌고 본문은 early return — 노드가 1에 park된다. SAVED→IDLE은 본문이 새로 돌아 라벨이 180ms에 걸쳐 페이드인한다(앱 부팅 시 최초 IDLE과 동일한 등장 방식 — gap truth의 "최초 IDLE과 동일하다" 요구를 충족).

    **(B) always-mounted 대안 판단을 코드 주석에 명시적으로 기록**

    UAT gap의 missing 항목 2("장기적으로 Animated.View를 항상 마운트하고 visibility만 토글")를 조용히 넘기지 말고, 교체한 effect 바로 위 주석 블록에 다음 3가지를 남긴다: (1) 근본 원인이 native-driver 리마운트 한계라는 것과 RN 이슈 번호, (2) 이 plan이 채택한 방식(의존성에 `showActionCard` + cleanup park), (3) always-mounted 방식을 **채택하지 않은 근거** — 03-UI-SPEC.md line 150이 버튼↔카드 교체를 "단순 조건부 렌더링"으로 확정했고, 항상 마운트해두면 액션 카드 아래에 히트 영역이 남아 오탭 위험이 생기며, cleanup park가 리마운트 함정을 같은 지점에서 이미 무력화하기 때문. 주석은 반드시 자기 줄에 쓴다(`<constraints>` 4번).
