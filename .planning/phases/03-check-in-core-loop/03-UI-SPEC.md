# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Boundary (read first)

Phase 3의 UI 표면은 D-06(최소 지도 화면)에 한정된다. 아래가 이 phase의 전체 UI 범위다:

1. **최소 지도 화면** — `react-native-maps` 전체화면 지도 + 플로팅 체크인 알약버튼. 바텀시트/오늘 체크인 리스트/이동 궤적선은 Phase 4 소관(REQ-today-view, REQ-trajectory-line) — 만들지 않는다.
2. **GPS 캡처 로딩 상태** — 체크인 버튼 자체가 로딩 상태로 전환(별도 모달 없음).
3. **확인 핀 플로우** — 드래그 가능한 확인 핀(3가지 시각 상태) + "확인" 액션 카드.
4. **저장 상태 전환** — 저장 중 → 저장 완료 / 저장 실패 + 재시도, 크로스페이드.
5. **메모/사진 입력 UI** — 저장 완료 후 기본 노출되는 액션시트 기반 사진 첨부 + 메모 텍스트 입력.
6. **위치 권한 거부 배너** — `NotificationDeniedBanner`와 동일 패턴의 `LocationDeniedBanner`.

**이 phase가 만들지 않는 것 (03-CONTEXT.md 근거):**
- 사진 리사이징 파이프라인 및 `documentDirectory` 최종 저장 규약 자체(REQ-photo-resize, Phase 4) — Phase 3는 원본을 `documentDirectory`에 복사(D-02)만 하고 화면에는 선택된 원본을 그대로 미리보기한다.
- 오늘 뷰 지도+바텀시트 완성형 UI(Phase 4) — Phase 3의 지도는 엣지투엣지 전체화면이며 바텀시트가 없다.
- 이동 궤적선(REQ-trajectory-line, Phase 4).
- `drafts` 테이블 스키마 자체(데이터 계층, 03-RESEARCH.md Pattern 4 참고 — UI-SPEC 범위 아님).
- 확인 핀 드래그의 VoiceOver 대체 경로(product-design.md에서 인지된 gap으로 유예됨, REQUIREMENTS.md REQ-accessibility-baseline 인수 조건에도 미포함) — Phase 3는 이 gap을 해소하지 않는다.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — React Native/Expo 프로젝트라 shadcn 해당 없음(shadcn gate는 React 웹/Next.js/Vite 전용, Phase 2 UI-SPEC과 동일 판정) |
| Preset | not applicable |
| Component library | none — `src/theme/tokens.ts` 상수를 직접 참조하는 커스텀 RN 컴포넌트(`StyleSheet.create`). 신규: `react-native-maps`(`MapView`/`Marker`)가 이 phase에서 처음 도입되는 지도 렌더링 프리미티브(03-RESEARCH.md Standard Stack) |
| Icon library | `expo-symbols`(SF Symbols) — Phase 1부터 설치돼 있으나 Phase 2는 미사용. Phase 3에서 처음 실사용: 사진 첨부 placeholder 박스의 카메라 아이콘 1곳에만 사용. 새 아이콘 라이브러리 추가 없음 |
| Font | 기존 3계층 그대로(DESIGN.md) — UI 크롬은 SF Pro(`typography.screenTitle`/`placeName`/`helperText`), 메모 텍스트 입력창은 `typography.journalEntry`(Newsreader 이탤릭 세리프, 사용자 작성 텍스트 전용 토큰이 이 phase에서 처음 실사용됨) |

**알려진 기술 제약(계획 단계에서 확인 필요) — 지도 커스텀 스타일링:** DESIGN.md/`tokens.ts`는 `colors.mapLand`/`mapRoad`/`mapWater` 3개 토큰을 정의해뒀지만, `react-native-maps`의 `customMapStyle` prop은 **Google Maps provider(`PROVIDER_GOOGLE`) 전용**이며 03-RESEARCH.md가 채택한 기본 provider는 API 키가 필요 없는 **Apple Maps(iOS 기본 provider, provider 미지정)**다. Apple Maps는 이 3개 색상 토큰으로 지도 베이스 스타일(땅/도로/물 색)을 커스터마이징할 방법을 제공하지 않는다. **Phase 3 실행자는 이 3개 토큰을 지도 베이스 렌더링에 적용하지 말고, iOS 기본 Apple Maps 스타일을 그대로 사용한다** — `colors.accent`/`accentSoft`는 지도 위에 얹는 마커(확인 핀)에만 적용해 토큰 계약을 지킨다. 이 gap은 계획 단계에서 창업자에게 명시적으로 확인 권장(2단계에서 `PROVIDER_GOOGLE` 전환 또는 mapLand/Road/Water 토큰 폐기 중 택1 필요).

## Typography

프로젝트는 범용 Body/Label/Heading이 아니라 `src/theme/tokens.ts`의 네임드 시맨틱 토큰을 쓴다. 아래는 그 토큰을 이 phase의 요소에 매핑한 것 — **새 크기/굵기를 추가하지 않고 기존 5개 토큰 중에서만 고른다**.

| Role | Token (tokens.ts) | Size | Weight | Line Height | 이 phase에서 쓰이는 곳 |
|------|--------------------|------|--------|-------------|------------------------|
| Heading | `typography.screenTitle` | 22px | 600 | 1.2 (기본) | 액션 카드의 "저장 완료" / "저장하지 못했어요" 헤드라인 — 화면의 "주인공"급 표시(작은 토스트 아님) |
| Label | `typography.placeName` | 16px | 500 | 1.2 (기본) | 체크인/확인/다시 시도 버튼 라벨, 사진 "변경" 링크 |
| Body/Helper | `typography.helperText` | 13px | 400 | 1.3 (기본) | 저장 실패 보조 문구, 핀 드래그 안내("핀을 옮겨 위치를 조정할 수 있어요"), 위치 배너 텍스트, 사진 추가 실패 인라인 문구 |
| Journal(사용자 작성 텍스트 전용) | `typography.journalEntry` | 15px | 400 | 1.5(22.5px) | 메모 입력 `TextInput`의 스타일 — placeholder와 실제 입력 텍스트 모두 이 스타일 적용(이탤릭 세리프가 "직접 쓰는 곳"임을 입력 전부터 신호) |
| Display | 해당 없음 | — | — | — | 이 phase에서 사용 안 함 |

**금지 사항:** UI 크롬(버튼 라벨, 헤드라인, 배너, 안내 문구)에는 `typography.journalEntry`를 절대 쓰지 않는다 — 메모 `TextInput` 단 하나의 요소에만 한정.

## Color

DESIGN.md/`tokens.ts`의 기존 팔레트를 그대로 사용 — 이 phase는 새 색상을 도입하지 않는다.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F4F1EA` (`colors.background`) | 지도 밖 여백이 없는 전체화면 지도 레이아웃이라 이 phase 화면 자체엔 거의 안 보이지만, 지도가 로드되기 전 초기 프레임의 배경으로 사용 |
| Secondary (30%) | `#FBFAF6` (`colors.surface`) | 액션 카드(확인/저장 상태/메모·사진 입력) 배경, 배너 배경, 사진 placeholder 박스 배경 |
| Accent (10%) | `#7C8660` (`colors.accent`) | **체크인 알약버튼**(DESIGN.md 6개 승인 용도 중 "체크인 버튼")과 **확인 핀의 신뢰 상태 표시**(승인 용도 "지도 마크") 단 2곳으로 한정 — 아래 "Pin Visual States"·"버튼 색상 결정" 참고 |
| Destructive | 해당 없음 | DESIGN.md에는 semantic 색상 시스템 자체가 없다 — 저장 실패도 muted 텍스트로만 표현(아래 Copywriting 참고), 빨강 계열 금지 |

**버튼 색상 결정 — accent 범위를 넓히지 않음(Phase 2 선례 그대로 계승):** "확인"/"다시 시도"/"완료" 버튼은 accent를 쓰지 않는다. DESIGN.md는 accent를 정확히 6개 용도로 제한하며 "체크인 버튼"은 지도 위 진입 알약버튼(체크인 알약버튼)을 가리킨다 — 이 세 버튼을 같은 용도로 해석해 accent를 확장하면 Decisions Log가 명시한 "액센트는 하나, 절대 늘리지 않는다" 원칙과 Phase 2 priming 화면이 이미 세운 선례(제품명 "허용하기" 버튼도 accent 미사용, 대신 `colors.textPrimary` 필 버튼 채택)에 어긋난다. 따라서:
- **체크인 알약버튼(진입, 지도 위 플로팅):** 배경 `colors.accent`, 텍스트 `colors.surface`. 로딩 중엔 배경만 `colors.accentSoft`로 전환(라벨은 `ActivityIndicator`, color `colors.accent`로 대체) — 180ms 크로스페이드(`motion.saveStateCrossfadeMs`).
- **"확인" / "다시 시도" / "완료" 버튼:** 배경 `colors.textPrimary`(#2F302C), 텍스트 `colors.surface` — priming.tsx의 "허용하기" 버튼과 동일 처리.
- **"나중에"/링크류 텍스트가 이 phase엔 없음** — 해당 사항 아님.

### Pin Visual States (03-CONTEXT.md "Claude's Discretion" 확정)

3가지 시각 상태로 5개 `location_source` 값을 표현한다 — 시맨틱 컬러(빨강/초록) 대신 accent/accentSoft의 채움·테두리 조합만으로 구분한다. 03-RESEARCH.md Open Questions #1의 권장 매핑을 그대로 채택.

| 시각 상태 | `location_source` | 채움(fill) | 테두리(stroke) | 의미 |
|-----------|--------------------|-----------|-----------------|------|
| 확정(Confident) | `gps_auto` | `colors.accent` 100% | 없음 | 5초 내 GPS 성공, 드래그 안 함 — 가장 신뢰도 높은 기본 상태 |
| 추정(Estimated) | `gps_low_accuracy_fallback` / `manual_denied` / `manual_no_signal` (드래그 전) | `colors.accentSoft` 100% | `colors.accent` 2px | 5초 타임아웃+OS캐시 폴백, 또는 권한 거부/신호 없음으로 자체 폴백 체인 사용 — "옅게 다르게"(product-design.md 확정 표현)로 3가지 원인을 동일하게 표시, 경고 아이콘·문구 없음 |
| 사용자 확인(User-placed) | `gps_dragged`(원 소스 무관, 드래그 발생 즉시 전이) | `colors.accent` 100% | `colors.accentSoft` 2px(외곽 halo) | 사용자가 직접 드래그로 최종 위치를 확정 — 자동 성공과 동일하게 "신뢰"를 뜻하는 실채움을 쓰되, 나중에 지도/리스트에서 "손으로 확인했다"는 걸 옅은 외곽 링으로만 구분(product-design.md: "일반 체크인과 시각적으로 살짝 구분") |

- **핀 형상 (2026-08-28 변경, DESIGN.md Decisions Log 참고):** 구글맵 스타일 물방울(teardrop) 마커, 뾰족한 끝이 실제 좌표를 가리킴(anchor 0.5/1). SVG 등 새 의존성 없이 28px 정사각형의 세 모서리만 완전히 둥글리고 한 모서리는 각지게 남긴 뒤 -45도 회전시키는 순수 View/StyleSheet 기법으로 구현. 원래 채택했던 24px 점(dot) 마커(2026-08-22 design-system variant C)는 iOS 네이티브 "내 위치" 파란 점과 겹쳐 구분이 어렵다는 실사용 피드백으로 교체됨 — 색상(accent/accentSoft) 팔레트와 3가지 시각 상태 매핑은 그대로 유지, 채움/테두리 조합도 동일하게 적용.
- **드롭 애니메이션:** `motion.confirmPinDropMs`(160ms) ease-out, 오버슈트/바운스 없음(DESIGN.md 확정 모션 — 새로 발명하지 않고 그대로 재사용).
- **드래그 시:** `onDragStart`에서 시각 변화 없음(그대로), `onDragEnd`에서 위 "사용자 확인" 상태로 즉시 전이(애니메이션 없이 채움/테두리 스왑 — 드롭 애니메이션과 별개, 새 모션 토큰 발명하지 않음).
- **"현재 위치" 표시:** 이 phase는 커스텀 accent 링을 쓰지 않는다 — `MapView`의 `showsUserLocation={true}`(iOS 네이티브 파란 점)로 충분(accent 예산을 확인 핀에만 쓰기 위한 의도적 절약). "현재 위치 링"(DESIGN.md 승인 용도)의 실제 커스텀 적용은 Phase 4 오늘 뷰가 필요 시 담당.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA(체크인 진입) | "체크인" — 지도 위 플로팅 알약버튼, 별도 설명 문구 없음(자기설명적) |

## Screen & Component Notes

### 최소 지도 화면 (D-06 — `src/app/index.tsx` 대체 또는 신규 라우트, 계획 단계에서 정확한 경로 결정)

레이아웃:
1. `MapView`(전체화면, edge-to-edge) — `showsUserLocation={true}`, provider 미지정(Apple Maps 기본).
2. 화면 상단(세이프에어리어 아래) — 배너 스택: `NotificationDeniedBanner`(Phase 2, 위) → `LocationDeniedBanner`(Phase 3, 아래) 순서로 세로 스택. 둘 다 해당 없으면 이 영역은 빈 공간(높이 0). **이것은 최종 위치가 아니다** — Phase 4가 오늘 뷰를 만들 때 두 배너 모두 지도 상단(탭바 위)으로 이관.
3. 화면 하단, 세이프에어리어 기준 `spacing.xl`(32px) 여백 — 체크인 알약버튼(48pt 높이, `radius.full`), 중앙 정렬. 확인 핀 플로우가 시작되면 이 버튼은 사라지고 아래 액션 카드로 대체된다(별도 전환 애니메이션 없음, 단순 조건부 렌더링).

### 확인 핀 → 저장 → 메모/사진 액션 카드

카드는 화면 하단에 고정된 표면(`colors.surface`, 상단 모서리만 `radius.lg`) — Phase 4의 정식 바텀시트를 흉내 내지 않되(드래그 스냅 없음), 나중에 그 자리를 대체할 것을 감안해 위치 계산 방식(세이프에어리어 하단 기준)은 동일하게 맞춘다. 카드 등장/퇴장은 `motion.bottomSheetSnapMs`(220ms) 재사용(Phase 4가 이 자리를 정식 바텀시트로 승격할 때 동일 타이밍이라 위화감이 없음). 카드 내부 좌우 패딩 `spacing.lg`(24px), 상단 패딩 `spacing.lg`, 섹션 간 세로 간격 `spacing.md`(16px).

**상태 전이(REQ-checkin-write-failure-ui, REQ-checkin-confirm-pin의 시각 계약):**

| 상태 | 트리거 | 카드 내용 |
|------|--------|-----------|
| CAPTURING | 체크인 버튼 탭 | 카드 없음 — 버튼 자체가 로딩 상태(위 Color 섹션 참고), 지도는 계속 보임 |
| CONFIRM | GPS 캡처 완료(성공/타임아웃/폴백 무관, 항상 도달) | 핀이 지도에 드롭(160ms) + 카드에 안내 문구(`helperText`) + "확인" 버튼 |
| SAVING | "확인" 탭 | 카드 내용이 180ms 크로스페이드로 `ActivityIndicator`(텍스트 없음)로 전환 — 자동 재시도 1회는 이 화면 안에서 조용히 일어나며 별도 상태로 노출되지 않음 |
| SAVED | insert 성공(자동 재시도 포함) | 180ms 크로스페이드 → "저장 완료"(`screenTitle`) + 그 바로 아래 사진 영역 + 메모 입력 영역이 기본 노출(접혀있지 않음) + 메모 입력 아래 "완료" 버튼 |
| SAVE_FAILED | insert 재시도까지 실패 | 180ms 크로스페이드 → "저장하지 못했어요"(`screenTitle`) + "저장 공간을 확인해주세요"(`helperText`, `textMuted`) + "다시 시도" 버튼. **사진/메모 입력 영역은 이 상태에서 아예 렌더링하지 않는다**(비활성화가 아니라 미마운트 — "저장 성공 전까지 메모/사진 입력을 막는다"의 구현 계약) |
| (SAVE_FAILED에서 이탈 시도) | 사용자가 뒤로 가기/탭 전환 | OS 네이티브 `Alert` 1회 노출("이 체크인은 저장되지 않았어요", 버튼 "확인") — 이탈 자체를 막지는 않음(정보 제공), 드래프트는 D-05에 따라 SQLite에 남아있어 다음 실행 시 복구 제안으로 이어짐(데이터 계층 책임, UI-SPEC 범위 아님) |

### 메모/사진 입력 영역 (SAVED 상태에서만 렌더링)

순서(위→아래, Phase 5 상세화면의 사진→메모 순서와 일관되게 유지):
1. **사진 영역** — 아직 선택 안 함: `colors.surfaceSoft` 배경 + `colors.line` 1px 테두리의 정사각형 placeholder 박스(최소 44×44pt, 권장 80×80pt), 중앙에 `expo-symbols` 카메라 아이콘(`colors.textMuted`) + 그 아래 "사진 추가"(`helperText`). 탭하면 `ActionSheetIOS`(OS 네이티브, 리테마 안 함) 노출. 선택 완료 시: 80×80pt 정사각 썸네일(`radius.md`, 8px 모서리), 우측 또는 하단에 "변경"(`placeName` 톤 축소, `textMuted`) 텍스트. 실패 시: 박스 바로 아래 "사진을 추가하지 못했어요"(`helperText`, `textMuted`) — 모달/토스트 없음.
2. 세로 간격 `spacing.md`(16px)
3. **메모 입력** — 멀티라인 `TextInput`, 스타일 `typography.journalEntry` 전체 적용(placeholder 포함), `placeholderTextColor: colors.textFaint`, 배경 `colors.surface`(카드와 동일, 별도 구분선 없이 자연스럽게 이어짐), 최소 높이 3줄 분량(약 68px, `journalEntry` line-height 22.5px 기준). 빨간 별표/"필수" 표시 없음 — placeholder 문구 자체가 초대하는 톤.
4. 세로 간격 `spacing.md`(16px)
5. **"완료" 버튼**(2026-08-28 추가) — 위 "확인"/"다시 시도"와 동일한 `primaryButton` 스타일(배경 `colors.textPrimary`, 텍스트 `colors.surface`, `radius.full`, 44pt 이상). 사진/메모는 필수가 아니므로 항상 활성 상태(비활성화 조건 없음). 탭하면 메모/사진을 flush하고 카드를 닫아 다음 체크인을 위한 초기 상태로 돌아간다 — 위 상태 전이표 "(SAVED에서 '완료' 탭)" 행 참고.

키보드 대응(구현 노트, 계획 단계 참고): 메모 입력에 포커스 시 카드가 하단 고정이라 iOS 키보드에 가려질 수 있음 — `KeyboardAvoidingView`(behavior: `padding`) 또는 동등한 처리가 필요. 이는 시각 계약이 아니라 구현 세부사항이므로 PLAN.md에서 태스크화할 것을 권장.

### 위치 권한 거부 배너 (`LocationDeniedBanner`)

`src/components/NotificationDeniedBanner.tsx`(Phase 2)와 **동일한 컴포넌트 계약**을 따르는 신규 파일 `src/components/LocationDeniedBanner.tsx`:
