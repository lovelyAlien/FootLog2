    `src/reflection/useReflectionDraft.ts`를 만들고 다음을 export한다:
    `export type ReflectionDraftBinding = { newPlaceAnswer: string; freeReflection: string;
    onChangeNewPlaceAnswer: (value: string) => void; onChangeFreeReflection: (value: string) => void;
    saveFailed: boolean; onRetry: () => void; flush: () => void; }` 와
    `export function useReflectionDraft(db: MigratableDb, dateKey: string): ReflectionDraftBinding`.

    동작 계약:
    (1) **로드** — `dateKey`가 바뀔 때마다 `getReflectionByDate(db, dateKey)`를 호출한다.
    행이 있으면 두 답변 state를 그 값(`null`은 빈 문자열로 정규화)으로 채우고 레코드 id를
    `recordIdRef`에 담는다. 없으면 두 답변을 빈 문자열로 두고
    `defaultCryptoDeps.randomUUID()`로 새 id를 만들어 `recordIdRef`에 담는다(아직 DB에
    쓰지 않는다 — 사용자가 아무것도 입력하지 않으면 빈 레코드를 만들지 않는다).
    로드 결과 반영은 `isMountedRef`와 `dateKeyRef`(`PastDateScreen.tsx`와 동일 관용구)로
    가드해, 스크러버로 빠르게 날짜를 옮길 때 늦게 도착한 응답이 최신 날짜의 입력을
    덮어쓰지 못하게 한다. 로드로 채운 값은 `controller.notify`를 호출하지 않는다(로드가
    저장을 유발하면 안 된다).
    (2) **입력** — `onChangeNewPlaceAnswer`/`onChangeFreeReflection`은 해당 state를 갱신하고
    `controller.notify({ dateKey, id: recordIdRef.current, newPlaceAnswer, freeReflection })`을
    병합된 최신 값으로 호출한다.
    (3) **저장** — 컨트롤러는 마운트 시 1회만 생성한다(lazy `useState` 초기화 또는 `useRef`).
    `onSave(draft)`는 `lastAttemptRef.current = draft`로 재시도용 값을 보관한 뒤
    `upsertReflection(db, { id: draft.id, date: draft.dateKey, newPlaceAnswer:
    draft.newPlaceAnswer, freeReflection: draft.freeReflection, now: toIsoTimestamp() })`을
    호출하고 결과로 `setSaveFailed(!result.ok)`한다. **`runWithSingleRetry`로 다시 감싸지
    않는다** — `upsertReflection`이 이미 내부에서 1회 재시도를 수행한다(이중 래핑은 최대
    4회 시도가 되어 D-01이 정한 "1회 자동 재시도" 계약을 깬다). 언마운트 후 setState를
    막는 `isMountedRef` 가드를 둔다.
    (4) **AppState flush** — `AppState.addEventListener('change', ...)` 안에서
    `if (nextAppState === 'active') return;` 가드를 먼저 두고(포그라운드 복귀마다 불필요한
    쓰기를 막는 기존 계약, 07-RESEARCH.md Pitfall 4) `controller.flush()`를 호출한다.
    cleanup에서 `subscription.remove()`.
    (5) **날짜 전환/언마운트 flush** — `dateKey`에 의존하는 effect의 cleanup에서
    `controller.flush()`를 호출한다. draft가 자신의 `dateKey`/`id`를 들고 있으므로 이
    flush는 **이전 날짜** 레코드에 정확히 기록된다(T-07-05). 마운트 해제 시에는 flush 이후
    `controller.dispose()`로 타이머를 정리한다.
    (6) **재시도** — `onRetry`는 `lastAttemptRef.current`가 있으면 그 draft로 저장을 다시
    시도한다(`SettingsScreen.tsx`의 `handleRetry`/`lastAttemptRef` 관용구와 동일 정신).
    (7) **flush 노출** — 반환값의 `flush`는 `controller.flush`를 그대로 노출한다. 모달의
    닫기 핸들러가 `flush()` 후 `router.back()`을 호출하는 순서를 07-05가 쓴다.

    이 파일에 SQL 문자열이나 한국어 문구 리터럴을 두지 않는다(각각 repo/content.ts 소관).
    5000 같은 디바운스 리터럴도 쓰지 않는다 — 컨트롤러 기본값을 그대로 쓴다.
