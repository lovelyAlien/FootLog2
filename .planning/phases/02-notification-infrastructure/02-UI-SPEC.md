# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Boundary (read first)

Phase 2의 UI 표면은 의도적으로 얇다. 아래 세 가지만 이 phase의 UI 범위다:

1. **알림 priming 화면** — 앱 최초 실행 시 OS 알림 권한 다이얼로그 전에 보여주는 커스텀 풀스크린 화면 1개.
2. **알림 거부 상태 배너** — 조용한 상태 표시 배너 1개 + 설정 딥링크.
3. **iOS 권한 프롬프트 문구 3종** (위치/카메라/사진 라이브러리) — `app.json`의 `ios.infoPlist`에 들어가는 정적 문자열. OS 네이티브 다이얼로그 안에 그대로 노출되는 텍스트이며, 별도의 커스텀 pre-prompt 화면은 이 phase에서 만들지 않는다(위치/카메라/사진 권한 자체는 Phase 3/4에서 실제로 요청됨 — Phase 2는 문구만 확정).

**이 phase가 만들지 않는 것 (CONTEXT.md D-01 근거):**
- 알림 빈도 선택 UI(매시간/3시간마다/끔) — priming 화면에 넣지 않는다. footlog-product-design.md 원본 스펙은 priming 화면에 빈도 선택기를 포함했으나, CONTEXT.md D-01/D-02가 이를 Phase 6(설정 화면)로 명시적으로 연기했다. Phase 2의 priming 화면은 **문구 + 허용 버튼 + 나중에 링크만** 가진 단순 화면이며, 앱은 하드코딩된 "매시간" 빈도로 동작한다.
- "FootLog" 워드마크 — REQ-app-name은 Phase 8 소관(REQUIREMENTS.md Traceability 참고). Phase 2 priming 화면에는 앱 이름을 넣지 않는다.
- 위치/카메라/사진 권한을 요청하는 실제 화면 UI — Phase 3(체크인)/Phase 4(사진 첨부)에서 맥락적으로 트리거됨. Phase 2는 그 프롬프트에 실릴 문구만 확정한다.
- 자가진단 재생성에 대한 사용자 대면 UI 신호 — D-07에 따라 `console.log`만 사용, 화면 요소 없음.

## Spacing Scale

Declared values (Phase 1 `src/theme/tokens.ts`에서 그대로 가져옴 — 이 phase가 새로 발명하지 않음):

| Token | Value | Usage |
|-------|-------|-------|
| 2xs | 4px | 배너 내부 아이콘-텍스트 간격(해당 없음, 아이콘 미사용) |
| xs | 8px | 배너 텍스트 ↔ "설정에서 켜기" 링크 사이 여백 |
| sm | 12px | priming 화면 버튼 내부 세로 패딩 |
| md | 16px | priming 화면 body 텍스트 ↔ 버튼 사이 여백, 배너 좌우 패딩 |
| lg | 24px | priming 화면 좌우 여백(화면 가장자리), 버튼 ↔ "나중에" 링크 사이 |
| xl | 32px | priming 화면 상단 여백(세이프에어리어 아래) |
| 2xl | 48px | 사용 안 함 이 phase에서는 |
| 3xl | 64px | 사용 안 함 이 phase에서는 |

Exceptions:
- **44×44pt 최소 터치 타겟** — priming 화면의 "허용하기" 버튼, "나중에" 링크, 배너 전체 탭 영역(설정 딥링크) 모두 44pt 이상 확보. REQ-accessibility-baseline은 Phase 8 소관이지만, 이 phase에서 만드는 3개 인터랙티브 요소는 처음부터 44pt 기준으로 만들어 나중에 재작업하지 않는다.

## Typography

프로젝트는 범용 Body/Label/Heading이 아니라 `src/theme/tokens.ts`의 네임드 시맨틱 토큰을 쓴다. 아래는 그 토큰을 이 phase의 요소에 매핑한 것 — **새 크기/굵기를 추가하지 않고 기존 5개 토큰 중에서만 고른다**.

| Role | Token (tokens.ts) | Size | Weight | Line Height | 이 phase에서 쓰이는 곳 |
|------|--------------------|------|--------|-------------|------------------------|
| Heading | `typography.screenTitle` | 22px | 600 | 1.2 (기본) | priming 화면의 안내 문구("매시간 알림으로 지금 어디 있는지 잠깐 기록해요") — 화면에서 유일하게 강조되는 텍스트 |
| Label | `typography.placeName` | 16px | 500 | 1.2 (기본) | "허용하기" 버튼 라벨, "나중에" 링크 텍스트 |
| Body/Helper | `typography.helperText` | 13px | 400 | 1.3 (기본) | 배너 텍스트("알림이 꺼져있어요 · 설정에서 켜기") |
| Display | 해당 없음 | — | — | — | 이 phase에서 사용 안 함(Display급 대형 타이포 요소 없음) |

**금지 사항:** `typography.journalEntry`(Newsreader 이탤릭 세리프)는 이 phase의 어떤 텍스트에도 사용하지 않는다 — 사용자 작성 텍스트 전용 토큰.

## Color

DESIGN.md/`tokens.ts`의 기존 팔레트를 그대로 사용 — 이 phase는 새 색상을 도입하지 않는다.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F4F1EA` (`colors.background`) | priming 화면 전체 배경 |
| Secondary (30%) | `#FBFAF6` (`colors.surface`) | 배너의 고정 배경 표면(불투명 바) |
| Accent (10%) | `#7C8660` (`colors.accent`) | **이 phase에서는 사용하지 않음** — 아래 "Accent 사용 안 함" 결정 참고 |
| Destructive | 해당 없음 | 이 phase에 파괴적 액션 없음(권한 거부는 파괴적 액션이 아님) — DESIGN.md는 애초에 semantic 색상 시스템 자체가 없음(빨강 계열 전면 금지) |

**Accent 사용 안 함 — 명시적 결정:** DESIGN.md는 accent(`#7C8660`)를 정확히 6개 승인된 용도(체크인 버튼, 현재 위치 링, 지도 마크, 이동 궤적선, 오늘 표시 밑줄, 스크러버 선택 표시)로만 제한하며, "액센트는 하나, 절대 늘리지 않는다"는 원칙이 Decisions Log에 명시돼 있다. Phase 2의 "알림 허용하기" 버튼은 저 6개 용도 중 어디에도 해당하지 않는다("지금·기록됨·살아있음"이라는 accent의 의미 축과 무관한 일회성 권한 요청 버튼) — 따라서 7번째 용도로 확장하지 않는다.

- **"허용하기" 버튼 (primary CTA):** 배경 `colors.textPrimary`(`#2F302C`, 웜 니어블랙) 채운 필(pill) 버튼, 텍스트 `colors.surface`(`#FBFAF6`, 밝은 표면색)로 대비 확보. Border radius: `radius.full`(9999px) — DESIGN.md의 "체크인 알약 버튼"과 동일한 필 형태를 재사용하되 색상은 accent가 아닌 중립 다크 톤.
- **"나중에" 링크:** 배경 없음, 텍스트 `colors.textMuted`(`#79786F`), 언더라인 없음.
- **배너 텍스트:** `colors.textMuted`(`#79786F`) — 배너 배경 `colors.surface`(`#FBFAF6`) 위, 대비비 검증 필요(체커가 4.5:1 기준으로 확인).

Accent reserved for: 체크인 버튼 · 현재 위치 링 · 지도 마크 · 이동 궤적선 · 캘린더 "오늘" 밑줄 · 날짜 스크러버 선택 위치 표시 — **6개 전부 이 phase 밖의 화면 요소이며, Phase 2는 이 목록에 아무것도 추가하지 않는다.**

## Screen & Component Notes

### Priming 화면 (`src/app/` 신규 라우트 — 정확한 경로는 계획 단계에서 expo-router 컨벤션에 맞춰 결정)

레이아웃(세로 스택, 화면 중앙 정렬):
1. 상단 여백 `spacing.xl`(32px, 세이프에어리어 아래)
2. Heading 텍스트(`typography.screenTitle`) — 좌우 여백 `spacing.lg`(24px), 가운데 정렬, 2줄까지 자동 줄바꿈 허용
3. 세로 간격 `spacing.md`(16px)
4. "허용하기" 필 버튼 — 좌우 여백 `spacing.lg`(24px), 최소 높이 44pt, `radius.full`
5. 세로 간격 `spacing.lg`(24px)
6. "나중에" 텍스트 링크 — 버튼과 시각적 위계 차이 명확(더 작고 muted)

배경은 `colors.background` 단색, 다른 화면 요소(지도, 리스트 등) 없음 — 이 화면은 지도 위에 겹치지 않으므로 Pitfall 6(배너-온-맵 대비 문제)은 여기 해당 없음.

### 알림 거부 배너 (임시 배치)

**배치 위치:** Phase 2 시점에는 오늘 뷰(Phase 4에서 빌드됨)가 아직 존재하지 않으므로, 이 phase의 배너는 현재 존재하는 부팅 확인 화면(`src/app/index.tsx`)에 임시로 렌더링한다. **이것은 최종 위치가 아니다** — Phase 4가 오늘 뷰를 빌드할 때 배너를 지도 상단(탭바 위, 세이프에어리어 아래)으로 이관해야 한다. Phase 2 실행자는 배너를 재사용 가능한 독립 컴포넌트(예: `src/components/NotificationDeniedBanner.tsx`)로 분리해, Phase 4가 import만으로 재배치할 수 있게 만들 것.

레이아웃:
- 화면 상단, 고정 배경(`colors.surface`)의 불투명 바 — 지도나 가변 배경 위에 얹지 않는다(Pitfall 6 회피).
- 좌우 패딩 `spacing.md`(16px), 상하 패딩 최소 `spacing.xs`(8px), 전체 탭 영역 44pt 이상.
- 텍스트 전체가 탭 가능 영역 — 탭 시 `Linking.openSettings()`.
- 아이콘 없음, 경고색 없음 — `typography.helperText` + `colors.textMuted` 단독.
- `AppState`가 `active`로 전환될 때마다 권한 상태를 재조회해 배너 표시 여부를 갱신(승인 시 배너 즉시 사라짐, 재거부 시 다시 나타남).
