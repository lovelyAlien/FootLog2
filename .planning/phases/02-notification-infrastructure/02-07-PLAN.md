`src/app/_layout.tsx`를 두 가지로 수정한다.

**(1) SafeAreaProvider 추가.** `react-native-safe-area-context`의 `SafeAreaProvider`로 트리를 감싼다. 위치는 `GestureHandlerRootView` 바로 안쪽, `SQLiteProvider` 바깥이다 — 즉 `GestureHandlerRootView > SafeAreaProvider > SQLiteProvider > (StatusBar, Stack)`. `src/app/priming.tsx`(Plan 06)가 `useSafeAreaInsets()`를 쓰는데 provider가 없으면 런타임에 값이 0이 되거나 에러가 나므로 이 배선이 필수임을 주석으로 명시한다.

**(2) 포그라운드 자가진단 리스너 추가.** 기존 스플래시 `useEffect` 바로 **아래에** 두 번째 `useEffect`를 형제로 추가한다. 반드시 `if (!fontsLoaded && !fontError) { return null; }` 조기 반환보다 **위쪽**에 둔다 — 조기 반환 아래에 훅을 두면 React의 훅 호출 순서 규칙이 깨진다. 이 제약을 주석으로 명시한다.

이펙트 본문: 의존성 배열은 빈 배열(`[]`)이며, 다음을 수행하는 로컬 함수 `runCheck`를 정의한다 — `runForegroundNotificationCheck()`를 인자 없이 호출(Plan 05가 `PHASE2_NOTIFICATION_SETTINGS`와 `defaultNotificationDeps`를 기본 인자로 둔다)하고, `.catch`에서 `console.error('[notifications] foreground check failed', error)`로 남긴다(프로미스를 조용히 삼키지 않는 repo 규약). 이펙트는 마운트 시 `runCheck()`를 1회 호출하고(콜드스타트 경로 — 신규 설치 시 최초 트리거 등록도 이 경로가 담당한다), `return subscribeToForegroundActive(runCheck);`로 구독 해제 함수를 클린업으로 반환한다.

`AppState`를 이 파일에서 직접 import 하지 않는다 — `subscribeToForegroundActive`가 이미 그 래퍼이며(Plan 04), 여기서 다시 `AppState.addEventListener`를 부르면 리스너가 두 개가 된다.

기존 `_layout.tsx`의 Pitfall 3 주석과 같은 형태로, 새 배선 규칙을 명시하는 헤더 주석을 추가한다: `runForegroundNotificationCheck`와 알림 권한 재확인 로직은 **이 하나의 `AppState` 리스너에서만** 호출한다. 화면 컴포넌트나 다른 `useEffect`에서 중복 호출하면 포그라운드 전환마다 자가진단이 N배로 돌아 불필요한 네이티브 왕복이 생긴다. (배너의 권한 재조회는 `useNotificationPermissionBanner` 훅이 자체 구독으로 처리하며, 그건 UI 표시용 상태라 자가진단과 별개 관심사다 — 이 구분도 주석에 남긴다.)

`SQLiteProvider onInit={migrateDbIfNeeded}` 배선은 그대로 유지한다. `migrateDbIfNeeded` 식별자 등장 횟수를 늘리지 않는다 — `foundation-wiring.test.ts` Test 2가 import 줄 제외 정확히 1회를 강제한다.

**(1) priming 리다이렉트 게이트.** 기존 `schemaVersion` 이펙트 옆에 두 번째 상태 `const [permission, setPermission] = useState<PermissionSnapshot | null>(null)`와 두 번째 `useEffect`를 추가한다. 이펙트는 기존 이펙트와 **동일한 `isMounted` 가드 형태**를 그대로 따라 `fetchNotificationPermission()`을 호출하고 결과를 `setPermission`하며, `.catch`에서 `console.error`로 남긴다(빈 의존성 배열).

렌더 시작부에서 `if (shouldShowPriming(permission)) { return <Redirect href="/priming" />; }`를 반환한다. `Redirect`는 `expo-router`에서 import한다. `permission`이 아직 `null`인 초기 프레임에는 `shouldShowPriming`이 `false`를 반환하므로(Plan 04 Test 16) 화면이 깜빡이며 리다이렉트되지 않는다. `router.replace()`를 이펙트 안에서 명령형으로 호출하지 않는다 — 마운트 타이밍에 따라 네비게이션 준비 전 호출로 경고가 나며, 선언형 `<Redirect>`가 expo-router의 권장 형태다. 이 판단을 주석으로 남긴다.

**(2) 거부 배너 렌더링.** 현재 `styles.container`가 `flex:1 + justifyContent:'center' + padding: spacing.lg` 하나로 화면 전체를 담당하는데, 배너는 화면 **상단 고정**이고 기존 내용은 **세로 중앙**이어야 하므로 컨테이너를 두 겹으로 나눈다: 바깥 `styles.screen`(`flex:1`, `backgroundColor: colors.background`, 패딩 없음)이 `<NotificationDeniedBanner />`를 첫 자식으로 두고, 그 아래 안쪽 `styles.content`(`flex:1`, `justifyContent:'center'`, `padding: spacing.lg`)가 기존 4개 `Text`를 감싼다. `backgroundColor`는 바깥으로 옮기고 안쪽에서 제거한다(중복 배경 지정 방지).
