`src/notifications/registry.ts`의 스텁을 구현으로 채운다.

`buildNotificationRegistry(settings)`: `expectedCheckinIds(settings.checkinFrequency)` 대신 **전체 후보**를 순회한다는 점에 주의한다 — 레지스트리는 "현재 켜져 있어야 하는 것"만이 아니라 "이 앱이 관리하는 트리거 전부"를 항목으로 갖고, 각 항목의 `isEnabled()`가 현재 설정을 보고 판정한다. 다만 체크인은 빈도에 따라 후보 id 자체가 달라지므로, 체크인 항목은 `expectedCheckinIds(settings.checkinFrequency)`로 만들되 `checkinFrequency === 'off'`일 때는 `expectedCheckinIds`가 빈 배열이 되어 항목이 사라지는 대신 **`CHECKIN_HOURLY_ID` 하나를 `isEnabled: () => false`인 항목으로 넣는다** — Test 3/8이 "off일 때 체크인 kind 항목의 isEnabled가 false이고 skippedDisabled에 담긴다"를 요구하기 때문이다. 이 비대칭(off일 때 대표 항목 1개만 비활성 상태로 존재)을 주석으로 명시한다: 자가진단 리포트가 "체크인 알림은 꺼져 있어서 건너뜀"을 표현할 수 있어야 하고, 그러려면 항목이 0개가 아니라 비활성 1개여야 한다.

각 항목의 `recreate`는 `(deps) => scheduleById(entry.id, deps)`로 Plan 03의 함수를 그대로 위임한다 — 트리거 형태/문구를 이 파일에서 다시 정의하지 않는다.

`selfHeal(settings, deps)`: migrations.ts의 형태를 따라 (1) 라이브 조회 → (2) 델타 계산 → (3) 델타만 적용.
- (1) `const actualIds = new Set((await deps.getAllScheduledNotificationsAsync()).map(n => n.identifier))`
- (2) 레지스트리를 순회하며 `isEnabled()`가 `false`인 항목은 `skippedDisabled`에 담고 **재생성하지 않는다**(Pitfall 2 가드 — 이 한 줄이 없으면 사용자가 끈 알림이 조용히 부활한다는 주석을 반드시 단다). `isEnabled()`가 `true`인데 `actualIds`에 없는 항목만 `missing`에 담는다. 단일 id 존재 확인이 아니라 항목 전체 순회 = 집합 단위 판정임을 주석으로 명시한다(Pitfall 3).
- 고아 계산: `orphaned = [...actualIds].filter(id => ALL_MANAGED_IDS.includes(id) && !expectedNotificationIds(settings).includes(id))`. `ALL_MANAGED_IDS` 조건이 앱 소유가 아닌 알림을 취소하지 않게 막는 가드임을 주석으로 명시(Pitfall 4 + 불가침 규칙).
- (3) `orphaned`를 먼저 `deps.cancelScheduledNotificationAsync`로 취소해 `cancelled`에 담고, 그다음 `missing`을 `entry.recreate(deps)`로 재생성해 `recreated`에 담는다.
