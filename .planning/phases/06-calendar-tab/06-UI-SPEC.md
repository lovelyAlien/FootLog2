# Phase 6 — UI Design Contract: Calendar Tab

> Visual and interaction contract for the month grid, past-date read-only view, floating date
> scrubber, and settings screen. Generated by gsd-ui-researcher from 06-CONTEXT.md (D-01~D-06),
> 06-RESEARCH.md, `docs/designs/calendar-date-scrubber.md` (CLEARED), `docs/designs/
> footlog-product-design.md` T10 + navigation section, and `DESIGN.md`. Verified by
> gsd-ui-checker.

This is a **native iOS/Expo app**, not a web app — there is no shadcn/Tailwind/CSS design
system. The project's single source of truth is `DESIGN.md` (repo root), transcribed verbatim
into `src/theme/tokens.ts`. Per `CLAUDE.md`: "Always read DESIGN.md before making any visual or
UI decisions... Do not deviate without explicit user approval." This UI-SPEC does not invent a
new token system — it declares which existing tokens apply to Phase 6's four new
screens/components and specifies the small number of genuinely new values (sizes/copy) that
`DESIGN.md` does not yet name, all derived from already-approved canonical docs.

## Typography

Existing project roles (`src/theme/tokens.ts` `typography`, already locked) mapped to this
phase's screens, plus the specific new size/weight combinations Phase 6 introduces (all reuse
existing approved sizes — 13/15/16/22px — and existing approved weights — 400/500/600; no new
size or weight is introduced). Exactly **4 distinct font sizes** (13/15/16/22) are used — see the
"Scrubber caption" row below for the one deliberate resize that keeps this count at 4. Exactly
**3 distinct font weights** (400/500/600) are used — see the note immediately below the table for
why this is an accepted, pre-existing exception rather than a new Phase 6 deviation.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Display (`screenTitle`, reused) | 22px | 600 | 1.2 | Settings screen title ("설정"), CheckinDetailScreen title (unchanged, reused via existing route) |
| Heading (month grid header, **new combination**) | 22px | 600 | 1.2 | Month/year label ("2026년 9월") — same size/weight as `screenTitle`, System font |
| Body (`placeName`, reused) | 16px | 500 | 1.2 | Settings row primary label ("알림 빈도" / "하루 마무리 알림" / "버전") |
| Body-muted (settings row value, **new combination**) | 16px | 400 | 1.2 | Settings row trailing value ("매시간" / version string) — same size as `placeName`, regular weight + `colors.textMuted`, System font |
| Label (`helperText`, reused) | 13px | 400 | 1.3 | Settings section headers ("알림" / "정보") in `colors.textMuted` — NOT `colors.accent` (see Color section, Pitfall 4) |
| Grid day number (**new combination**) | 15px | 400 | 1.2 | Month grid day-of-month numerals, System font; color varies by state (see Component: Month Grid) |
| Weekday header (**new combination**) | 13px | 400 | 1.2 | "일 월 화 수 목 금 토" row, `colors.textFaint`, System font |
| Timestamp (`timestamp`, reused unchanged) | 15px | 500 | tabular-nums | Past-date view detail/list rows — identical to Today view, `ui-monospace` |
| Scrubber caption (**merged into Label role, resized — user-approved 2026-09-01**) | 13px | 400 | 1.3 | "← 드래그해서 날짜 이동 → · 오늘 이후로는 못 넘어감", `colors.textMuted` — resized from `calendar-date-scrubber.md`'s literal "11px" text up to 13px so this spec stays within the project's established 4-size type scale (UI-checker Dimension 4, BLOCK resolved by explicit user decision). This is a deliberate 1px adjustment to the caption's font size only; every other CLEARED contract in `calendar-date-scrubber.md` — position math, hard clamp at range boundaries, no momentum, 44×44pt drag-surface touch target, 44pt header — remains unchanged and is not affected by this resize. |

**Font-weight count note (UI-checker Dimension 4, BLOCK resolved by explicit user decision,
2026-09-01):** This spec uses 3 distinct weights — 600 (`screenTitle`/Heading), 500
(`placeName`/`timestamp`), 400 (`helperText`/body-muted/grid day number/weekday header/scrubber
caption). All three weights already exist in `src/theme/tokens.ts` and have shipped in
production since Phases 3–5 (`screenTitle` at 600, `placeName`/`timestamp` at 500,
`helperText`/`journalEntry` at 400) — Phase 6 introduces **zero new weight values**, it only
reuses existing roles on new screens. The UI-checker's 2-weight-per-phase cap exists to stop a
phase from *introducing* a new weight, not to retroactively flag tokens that already ship
project-wide. The user has explicitly approved this 3-weight count as a documented exception for
Phase 6's checker pass — do not attempt to collapse any existing role to a different weight to
force a count of 2; that would itself be an undocumented deviation from shipped tokens.

## Color

Existing project palette (`src/theme/tokens.ts` `colors`, already locked). Phase 6 introduces
**zero new color tokens** — D-04 explicitly reuses `calendar-multiselect-view.md`'s already-
defined muted-tone scheme instead of adding new hex values.

| Role | Value | Usage in Phase 6 |
|------|-------|-------------------|
| Dominant (60%) | `#F4F1EA` (`colors.background`) | Month grid background, past-date view screen background, settings screen background |
| Secondary (30%) | `#FBFAF6` (`colors.surface`) | Settings row backgrounds, scrubber floating card background, grid cell "today" background if any card treatment |
| Accent (10%) | `#7C8660` (`colors.accent`) | Reserved for exactly 2 uses in this phase, per `DESIGN.md`'s locked accent budget (do not add a 3rd use anywhere in this phase — see Pitfall 4 below): (1) today's underline in the month grid, (2) the scrubber's selected-tick + fixed center indicator line |
| Destructive | `#B85C38` (`colors.pin`) | Reused unchanged from `CheckinListRow`'s existing swipe-to-delete affordance when that row component is reused inside the past-date view's list (see Component: Past-Date View). Not a new usage — same component, same color, same undo pattern. No new destructive action is introduced in Phase 6 (settings screen has no delete-all row per D-02). |

**Accent reserved for (explicit, exhaustive — matches `DESIGN.md`'s locked budget for this
phase):**
1. Month grid — underline beneath today's day number
2. Date scrubber — selected tick mark (bold/long) + the fixed center selection indicator line

**Muted-tone record-presence scheme (D-04, reused verbatim from `calendar-multiselect-view.md`,
NOT new tokens):**

| State | Color | Token |
|-------|-------|-------|
| Day, unselected, has a checkin record | `#79786F` | `colors.textMuted` |
| Day, unselected, no checkin record | `#A7A49A` | `colors.textFaint` |
| Today (regardless of record presence) | day number in `colors.textPrimary` + accent underline below | `colors.accent` (underline only) |
| Day outside the visible month (leading/trailing grid padding) | `colors.textFaint` at reduced visual weight (same color as no-record, additionally lower opacity via `colors.textFaint` is already a light tone — do not introduce a new opacity value; if a cell needs to visually recede further, render it non-interactive instead of adding a new color) | `colors.textFaint` |

**Pitfall guard (carried forward from 06-RESEARCH.md Pitfall 4 — MANDATORY for the settings
screen):** The approved settings mockup (`settings-and-delete-20260822/settings-screen.png`,
viewed this session) renders section headers ("알림"/"데이터"/"정보") in an olive-brown tone that
visually resembles `colors.accent`. This mockup predates the accent-budget lock-down
(2026-08-23/08-31 `DESIGN.md` updates). **Do not use `colors.accent` for section headers.** Use
`colors.textMuted` instead — visually close enough to the mockup's intent without opening a
third accent use. Any `colors.accent` reference outside the two reserved uses above is a
contract violation.

## Component Contracts

### 1. Month Grid (`src/calendar/CalendarGridScreen.tsx`, replaces `calendar.tsx` placeholder)

**Layout:** Header row (44pt height) — `<` arrow button (44×44pt, accessibility label
`"이전 달"`) — month/year label (centered, Heading role, 22px/600) — `>` arrow button (44×44pt,
accessibility label `"다음 달"`). Below: weekday header row (7 columns, 13px `textFaint`, Sunday
first per D-06). Below: 7-column grid, N rows (5–6 depending on month), each cell minimum
44×44pt.

**Cell states (mutually applicable, not mutually exclusive except today+no-record which cannot
co-occur with "no record" muted styling on the underline itself):**

| State | Day number color | Additional treatment |
|-------|-------------------|------------------------|
| Today, has record | `colors.textPrimary` | `colors.accent` underline below number |
| Today, no record | `colors.textPrimary` | `colors.accent` underline below number |
| Past/present day (not today), has record | `colors.textMuted` (`#79786F`) | none |
| Past/present day (not today), no record | `colors.textFaint` (`#A7A49A`) | none |
| Future day (any) | `colors.textFaint` | still tappable (D-01 canonical_refs: no special future-date handling, falls through to the existing "아직 기록이 없어요" empty state via reused CheckinDetailScreen-style flow — actually via `PastDateScreen`'s own empty state above, since future dates and past dates share the same `[date].tsx` route and empty-state copy) |
| Outside visible month (leading/trailing padding cells) | `colors.textFaint`, non-interactive | Do not register `onPress` — these render for grid-alignment only |

**Interaction:** Tap any in-month day cell (including future dates and today) → `router.push`
to `calendar/[date].tsx`. No long-press, no drag-to-multiselect in this phase (that gesture is
explicitly Phase 2/deferred per D-01 canonical_refs and `calendar-multiselect-view.md`'s own
T1b deferral). Swipe left/right on the grid area OR tap header arrows → change visible month
(D-05, both required, swipe primary + arrows for discoverability/accessibility). No swipe
animation duration is separately specified — reuse `motion.easing.move` (ease-in-out), no new
motion token.

**Data:** One range query per visible month (`WHERE local_date_key BETWEEN ? AND ?`, reusing
`idx_checkins_local_date_key`) returning distinct date keys with records — re-fetched on month
change (06-RESEARCH.md Open Question 2 recommendation: no prefetch until proven laggy).

### 2. Past-Date View (`src/calendar/PastDateScreen.tsx`, route `calendar/[date].tsx`)

**Layout:** Reuses the exact map+bottom-sheet visual structure already shipped for Today view
(`src/today/TodayBottomSheet.tsx` + map), with two differences:

1. **No floating checkin button** — the one and only structural removal vs. Today view (REQ-past-date-view).
2. **Tab bar hidden** — unlike Today view and unlike the settings screen, this is the one screen
   in Phase 6 that hides the bottom tab bar (Pattern 3, imperative `getParent().setOptions()`
   override on mount, restored on unmount).

**List rows:** Reuse `CheckinListRow` unchanged — same swipe-to-delete (Pin-colored affordance,
4s undo snackbar) and same tap-to-detail (→ existing `CheckinDetailScreen`) behavior as Today
view. "읽기전용" (read-only) in REQ-past-date-view's wording refers specifically to the absence
of a *new-checkin* entry point on this screen — it does not mean existing records become
uneditable. Editing/deleting an existing past checkin still routes through the same, already-
approved `CheckinDetailScreen` (05-CONTEXT.md D-01: explicit unsaved-change warning model,
reused without modification) and the same swipe-delete pattern already shipped in Phase 5. This
is a UI-SPEC clarification, not a re-litigation of REQ-past-date-view — flag to planner if this
reading is contested.

**Empty state:** `"이 날은 기록이 없어요"` (see Copywriting Contract) on the bottom-sheet surface,
never over the map.

**Floating date scrubber:** See Component 3 below — appears only on this screen, only when ≥2
distinct dates in history have at least one checkin (`calendar-date-scrubber.md` Premise 11).

### 3. Date Scrubber (`src/calendar/DateScrubber.tsx`)

**Fully specced and CLEARED in `docs/designs/calendar-date-scrubber.md`** — this UI-SPEC
references, not re-derives, that document. Executor and checker MUST read it directly for exact
gesture/position math. Summary for quick reference only:

- Independent floating card, `colors.surface` background, `radius.lg` (16px) corners, subtle
  shadow — same surface tone as bottom sheet.
- Positioned 132pt above screen bottom (100pt CLOSED sheet peak + 32pt margin), fixed regardless
  of sheet state.
- Header: 44pt.
- Ticks: no record = `colors.line` (`#DDD8CD`) thin/short; has record = `#C7C2B4`
  slightly-longer/darker (this is the one net-new hex value in this phase — sourced directly
  from the CLEARED canonical doc, not invented here); selected day = `colors.accent`
  thick/long.
- Fixed center indicator line in `colors.accent` — the scrubber's second (and last) approved
  accent use.
- Touching the scrubber force-collapses the bottom sheet to CLOSED (220ms, reuses
  `motion.bottomSheetSnapMs` — no new motion token) via `bottomSheetRef.snapToIndex(0)`.
- Real-time 1:1 drag tracking, no momentum, hard-clamped at range boundaries (first checkin date
  ↔ today) — no rubber-banding.
- Whole gesture-detector surface ≥44×44pt (not per-tick hit slop).
- Caption below ticks: `"← 드래그해서 날짜 이동 → · 오늘 이후로는 못 넘어감"`, 13px muted (merged
  into the Label role — see Typography section for the 11px→13px resize rationale).
- Hidden entirely when 0–1 distinct dates have records.

### 4. Settings Screen (`src/settings/SettingsScreen.tsx`, route `(tabs)/index/settings.tsx`)

**Entry point:** Hamburger icon (≡, `line.3.horizontal`, `expo-symbols`) in the Today view
header — D-03: this icon lives on the Today view (`src/app/(tabs)/index/index.tsx`), NOT on the
calendar tab. It is not part of the tab bar (settings is not promoted to a tab, per the original
product spec's "설정은 탐색 목적이 아니므로 탭으로 승격하지 않는다" principle).

**Layout:** iOS grouped-list style (per the approved mockup, `settings-and-delete-20260822/
settings-screen.png`, viewed this session), reproduced as hand-rolled `View`/`Pressable`
components on `colors.background`, NOT `@expo/ui`'s native SwiftUI `List` (06-RESEARCH.md
explicit rejection — native chrome would be the only screen in this app breaking the custom
warm-palette convention). Header: `<` back chevron (44×44pt, accessibility label `"뒤로"`) +
centered title `"설정"` (Display role, 22px/600).

**Rows — exactly 3, per D-02 (mockup's 4th "전체 데이터 삭제" row is explicitly NOT included):**

1. Section "알림" (`colors.textMuted`, Label role — NOT accent, see Pitfall 4 guard above)
   - Row: "알림 빈도" | trailing value ("매시간"/"3시간마다"/"끔") | chevron `>` | tap →
     `ActionSheetIOS` 3-option picker → on selection: persist to `app_settings` SQLite row →
     call `applyNotificationSettings(settings, defaultNotificationDeps)` (existing function,
     reused unchanged, not reimplemented — 06-RESEARCH.md Don't Hand-Roll table)
   - Row: "하루 마무리 알림" | trailing `Switch` (default ON) | no chevron | toggle → persist →
     call `applyNotificationSettings` (same function, same call pattern)
2. Section "정보" (`colors.textMuted`)
   - Row: "버전" | trailing version string (`Constants.expoConfig?.version`) | **no chevron, not
     tappable** (visually distinct — this is the one read-only row)

**Row background:** `colors.surface` (`#FBFAF6`), grouped visually via `colors.background`
gutters between sections — matches the mockup's card-on-background composition, minus the
accent-toned section-header color (replaced with `colors.textMuted` per the pitfall guard).

**Tab bar:** stays visible on this screen (default nested-stack behavior, Pattern 2 — do NOT
add any `tabBarStyle` override here; this screen is architecturally equivalent to
`CheckinDetailScreen`, both push screens that keep the tab bar per `footlog-product-design.md`'s
navigation diagram, D-07 canonical_refs).
