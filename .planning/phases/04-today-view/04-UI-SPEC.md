# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Boundary (read first)

Phase 4의 UI 표면은 오늘 뷰를 "임시 전체화면 지도"(Phase 3)에서 앱의 영구 홈 화면(지도+3단 스냅 바텀시트+상시 탭바)으로 승격하는 것에 한정된다. 아래가 이 phase의 전체 UI 범위다:

1. **오늘 뷰 지도 + 3단 스냅 바텀시트** — CLOSED/DRAGGING/OPEN, 220ms. 리스트는 오늘 저장된 체크인만 시간순(REQ-today-view).
2. **저장된 체크인 지도 핀 + 이동 궤적선** — `accentSoft` 팔레트, 새 데이터 모델 없음(REQ-trajectory-line).
3. **플로팅 체크인/재센터 버튼의 바텀시트 연동** — 시트 상태와 무관하게 항상 접근 가능(D-05).
4. **하단 탭바 셸(RootTabNavigator)** — 오늘/캘린더 2탭, 캘린더는 플레이스홀더 텍스트 한 줄(D-06~D-09).
5. **사진 리사이징 실패 인라인 문구** — 새 UI 상태 아님, Phase 3의 기존 "사진을 추가하지 못했어요" 문구를 리사이징 실패 케이스까지 그대로 확장 재사용(REQ-photo-resize — 시각 계약 자체는 신규 아님).
6. **온보딩/위치 권한 맥락적 요청** — 신규 UI 없음, Phase 2/3 기존 흐름의 회귀 확인 대상(REQ-onboarding-empty-state).

**이 phase가 만들지 않는 것 (04-CONTEXT.md 근거):**
- 장소명(리스트 행) 필드 — D-01, 오프라인 원칙과 충돌해 아예 만들지 않음. DESIGN.md `typography.placeName` 토큰은 정의만 남고 이 phase에서 미사용.
- 리스트 행 탭 인터랙션/상세화면 — D-03, Phase 5(REQ-checkin-detail-base) 소관. 화살표 등 탭 가능함을 암시하는 시각 요소를 넣지 않는다.
- 캘린더 탭 실제 콘텐츠(월 그리드/과거 날짜 뷰/스크러버) — Phase 6.
- 햄버거 메뉴 아이콘 및 설정 화면 — D-08, Phase 6.
- "오늘 돌아보기" 회고 진입 행 — Phase 7(REQ-reflection-today-entry). 바텀시트 리스트 최상단 고정 행은 이 phase에 없음.
- 사진 액션시트/픽커 UI 자체 — Phase 3에서 이미 완성(`ActionSheetIOS`, 03-UI-SPEC.md). 이 phase는 픽커 결과에 리사이징 단계 하나만 끼워 넣는다 — 새 화면/모달 없음.

- **44×44pt 최소 터치 타겟** — 체크인 버튼, 재센터 버튼, 탭바 각 탭 히트 영역, 바텀시트 핸들의 드래그 히트 영역(시각적으로는 36×4px 얇은 바지만 `hitSlop`으로 확장) 모두 44pt 이상.
- **리스트 행은 비인터랙티브(D-03)이므로 44pt 터치 타겟 규칙이 강제되지 않는다** — 다만 가독성과 기존 리듬 유지를 위해 행 최소 높이는 44px로 맞춘다(우연히 터치 규칙과 같은 숫자이지만 근거는 "탭 가능"이 아니라 "일관된 리스트 밀도").
- **바텀시트 CLOSED 피크 높이:** 핸들 영역(`spacing.sm` 상하 여백 + 4px 핸들 바) + 리스트 행 1개 높이(44px) = 총 약 **80px**(탭바 상단 기준, 아래 "네비게이션 탭바" 절 참고). 체크인이 0건이면 리스트 행 대신 empty state 한 줄이 동일 높이를 차지.

## Color

DESIGN.md/`tokens.ts`의 기존 팔레트를 그대로 사용 — 새 색상 토큰 도입 없음.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F4F1EA` (`colors.background`) | 지도가 로드되기 전 배경, 화면 여백 |
| Secondary (30%) | `#FBFAF6` (`colors.surface`) | 바텀시트 표면, 탭바 배경, 배너 배경(Phase 2/3 계승) |
| Accent (10%) | `#7C8660` (`colors.accent`) | **체크인 알약버튼**(Phase 3 계승, 신규 아님) 단 1곳 — 이 phase는 accent 사용처를 늘리지 않는다 |
| Accent soft | `#D8DDC9` (`colors.accentSoft`) | **저장된 체크인 핀**(D-10, 신규) + **이동 궤적선**(신규 — 아래 "색상 결정: 궤적선" 참고) |
| Destructive | 해당 없음 | 이 phase에 파괴적 액션 없음(스와이프 삭제는 Phase 5) |

Accent 예산 확인: DESIGN.md의 6개 승인 용도 중 이 phase가 실제로 그리는 건 "체크인 버튼"(기존, accent) + "지도 마크"(신규, 저장된 핀 — 단 `accent`가 아니라 `accentSoft`) + "이동 궤적선"(신규, `accentSoft`) 3곳뿐이다. 새 색상을 추가하지 않았으므로 "액센트 1개, 절대 늘리지 않음" 원칙 위반 없음.

### 색상 결정: 궤적선 — `accent`가 아니라 `accentSoft` (DESIGN.md 내부 모순 해소)

04-RESEARCH.md Open Question #1이 발견한 실제 문서 간 모순을 이 UI-SPEC이 명시적으로 확정한다:
- DESIGN.md Color 섹션의 압축 리스트는 "이동 궤적선"을 accent(진한 올리브) 6개 승인 용도 중 하나로 문자 그대로 나열한다.
- 반면 같은 기능을 설명하는 `footlog-product-design.md`의 산문(오늘의 이동 궤적 — 보상 신호 절)은 "아주 얇고 채도 낮게(**포인트 컬러보다 옅은 톤**)"라고 못 박는다 — 즉 확인 핀(`accent`)보다 옅어야 한다.

**결정: `colors.accentSoft`, `strokeWidth: 2`, 실선.** 근거:
1. D-10이 이미 저장된 핀을 "포인트 컬러보다 옅은 톤"(`accentSoft`)으로 확정했다 — 같은 화면에서 궤적선만 진한 `accent`를 쓰면 확인 핀(진행 중, 진한 accent)과 저장된 핀+궤적선(과거, 옅은 accentSoft)이라는 이미 세운 "지금 vs 이미 기록됨" 위계가 깨진다.
2. `accent`를 지도 위 2곳(핀+선)에 동시에 쓰면 "액센트는 한 종류의 강조"라는 원칙이 시각적으로 흐려진다 — `accentSoft`는 새 토큰이 아니라 이미 승인된 옅은 변형이므로 예산을 늘리지 않는다.

**실선 vs 점선:** DESIGN.md Decisions Log(2026-08-22 항목)는 궤적선을 "얇은 점선"이라 부르지만, 같은 문서의 상세 절(위 인용)과 REQUIREMENTS.md/04-CONTEXT.md는 모두 그냥 "얇고 채도 낮은 선"이라고만 하고 점선 여부를 특정하지 않는다. **이 phase는 실선을 기본값으로 채택**한다 — 점선(끊긴 선)이 오히려 GPS 트래킹 앱의 이동 경로 표기(내비게이션 경로처럼 보이지 않게 하자는 원래 취지와 반대 방향)에 더 가깝게 읽히기 때문. 체커/창업자가 점선을 원하면 `lineDashPattern={[4, 4]}`로 전환은 저비용(react-native-maps `Polyline` prop 하나).

### 네비게이션 탭바 — 기본 활성 탭 틴트가 iOS 시스템 블루임에 주의

expo-router `Tabs`를 커스텀 설정 없이 그대로 쓰면 활성 탭 아이콘/라벨이 iOS 기본 파란색(`tabBarActiveTintColor` 미지정 시 네비게이션 테마 기본값)으로 렌더링된다 — 이는 DESIGN.md의 "액센트 1개(올리브그린), 시맨틱 색상 없음, 빨강/파랑 계열 배제" 원칙과 정면으로 충돌하는, 놓치기 쉬운 기본값 함정이다. **명시적으로 오버라이드 필요:**
- `tabBarActiveTintColor: colors.textPrimary`(#2F302C) — accent를 탭 강조에 새로 쓰지 않는다("탭 아이콘 강조 없음 — 시스템 기본 탭바 스타일", DESIGN.md Layout §Border radius 주석 근거).
- `tabBarInactiveTintColor: colors.textMuted`(#79786F)
- `tabBarStyle: { backgroundColor: colors.surface, borderTopColor: colors.line, borderTopWidth: 1 }`

```
RootTabNavigator (하단 탭바, colors.surface 배경, 항상 노출)
└── 오늘 탭
     └── MapView (edge-to-edge, showsUserLocation, provider 미지정 — Phase 3 그대로)
          ├─ 저장된 체크인 핀 (accentSoft teardrop, 시간순)
          ├─ Polyline 궤적선 (accentSoft, 2px, 실선 — 위 "색상 결정" 참고)
          ├─ 확인 핀(체크인 진행 중에만, Phase 3 3단계 시각 상태 그대로 — 이 phase는 손대지 않음)
          ├─ 배너 스택 (상단, 세이프에어리어 아래 — NotificationDeniedBanner → LocationDeniedBanner)
          ├─ [D-04 분기 A] showActionCard === false:
          │     ├─ TodayBottomSheet (CLOSED/DRAGGING/OPEN, colors.surface, 상단만 radius.lg)
          │     └─ 플로팅 체크인/재센터 버튼 — bottom = 시트 현재 상단(animatedPosition) + spacing.lg, 연속 추적
          └─ [D-04 분기 B] showActionCard === true:
                └─ CheckinActionCard만 (Phase 3 그대로, 바텀시트 자리에 배타적으로 렌더링 — 언마운트 방식)
                     — 정정(04-06-PLAN.md Task 1, option-a 채택, 2026-08-31): 체크인 버튼과
                     재센터 버튼 둘 다 렌더하지 않는다(둘 다 언마운트). 이 줄이 이전에 "재센터
                     버튼만은 계속 보인다"고 적었던 것은 실제 Phase 3 코드 동작에 대한 사실
                     오인이었다 — Phase 3 코드는 showActionCard가 true인 동안 두 버튼을 모두
                     언마운트한다. 창업자가 Phase 3 동작을 그대로 유지하기로 선택(회귀 위험 0,
                     확인 핀 확정 중 지도를 옮길 이유 없음 — 핀을 잃어버리는 혼란 방지)해 이
                     문서를 코드 실제 동작에 맞춰 정정한다.
```

**구현 시 확인 필요(설계 계약이 아니라 배치 검증 항목):** 오늘 화면이 `(tabs)` 라우트 그룹으로 이동하면 화면 콘텐츠 영역이 이미 탭바 위에서 끝난다 — 기존 `insets.bottom`(물리적 세이프에어리어) 기준 오프셋 계산이 탭바 도입 후에도 여전히 유효한지(탭바가 별도로 세이프에어리어를 소비하는지, 화면 콘텐츠가 탭바 높이만큼 이미 줄어드는지) iOS 시뮬레이터에서 실측 확인할 것 — 시각 계약(오프셋 = 시트 상단/화면 하단 + `spacing.lg`/`spacing.xl`)은 그대로, 그 기준선이 어느 좌표계인지만 구현 단계 검증 대상.

### 바텀시트 (`@gorhom/bottom-sheet`)

- **핸들:** 36×4px 바, `colors.line`, `radius.full`, 상단에서 `spacing.sm`(12px) 여백. 드래그 히트 영역은 44×44pt로 확장.
- **표면:** `colors.surface`, 상단 모서리만 `radius.lg`(16px), 하단 모서리 없음(탭바에 맞닿음).
- **CLOSED:** 핸들 + 리스트 첫 행(또는 empty state) 한 줄만 노출, 총 높이 약 80px(위 Spacing Scale Exceptions 참고), 탭바 상단 기준.
- **DRAGGING:** 실시간 추적(스냅 지점 도달 전까지는 손가락 위치를 그대로 따라감) — `onChange`가 아니라 `animatedPosition`/`animatedIndex` 같은 연속값을 버튼 오프셋 계산에 써야 하는 이유(D-05)가 바로 이 상태.
- **OPEN:** "화면 대부분"(전체 아님) — 상단에 `insets.top + spacing.xl`만큼 지도가 항상 보이도록 남겨, OPEN 상태에서도 사용자가 방향 감각(지도 컨텍스트)을 잃지 않게 한다. 100% 풀스크린 시트는 만들지 않는다.
- **애니메이션:** 3개 스냅포인트 전환 모두 `motion.bottomSheetSnapMs`(220ms) — 새 모션 토큰 발명 없음.
- **리스트 렌더링:** 반드시 `BottomSheetFlatList`(플레인 `FlatList` 금지 — 04-RESEARCH.md Anti-Pattern, 시트 팬 제스처와 스크롤 제스처 충돌 방지).

### 리스트 행 (`CheckinListRow`)

- 좌우 패딩 `spacing.lg`(24px), 상하 패딩 `spacing.sm`(12px), 행 최소 높이 44px.
- 행 사이 구분선: `colors.line` 1px hairline(카드로 감싸지 않음, 플랫 리스트).
- 내부 구성(가로 배치): `typography.timestamp` 시간(고정 폭, 왼쪽) — 메모가 있으면 오른쪽에 `typography.journalEntry` 메모 미리보기 1줄(ellipsis). 메모 없으면 시간만, 두 번째 요소 자체를 렌더링하지 않음(빈 자리로 남겨두지 않음 — 자유형 체크인 모델과 일관되게 "없으면 그냥 없다").
- 사진 유무를 나타내는 아이콘/뱃지 없음(D-02).
- 탭 피드백(ripple, highlight, chevron) 없음(D-03) — `Pressable`/`TouchableOpacity`로 감싸지 않고 순수 `View`.

### 저장된 체크인 핀 (지도)

- 형상: Phase 3의 teardrop `pinWrapper`/`pinDrop` 스타일 그대로 재사용(28×34px, -45도 회전 기법).
- 색상: `colors.accentSoft` 단색 채움, 테두리 없음 — **원본 `location_source`(GPS 성공/폴백/드래그)에 따른 시각 구분을 저장 후에는 유지하지 않는다.** Phase 3의 3단계 핀 상태(확정/추정/사용자 확인)는 "지금 확인 중"인 확인 핀에만 의미가 있고, 저장되고 나면 D-10이 정의한 단일 `accentSoft` 규칙으로 단순화된다 — 지도 위 시각적 복잡도를 늘리지 않기 위한 의도적 절약.
- 확인 핀(진행 중, `colors.accent`)과 저장된 핀(`colors.accentSoft`)이 동시에 화면에 보이는 경우는 없다 — D-04에 따라 확인 핀 플로우가 떠 있는 동안 바텀시트/저장된 핀 목록 갱신이 사용자 눈에 노출될 필요가 없으므로 혼동 위험 낮음(단, 이미 저장된 오늘의 다른 핀들은 확인 핀 플로우 중에도 지도에 계속 보인다 — 숨기는 대상은 바텀시트뿐).

### 이동 궤적선 (`Polyline`)

- 좌표: `getTodayCheckins` 결과를 `timestamp_utc` 오름차순 그대로 연결(이미 정렬된 쿼리, 별도 정렬 로직 불필요).
- 체크인 0~1개: 선 렌더링 안 함(폴리라인 좌표 배열이 2개 미만이면 컴포넌트 자체를 마운트하지 않음).
- 스타일: `strokeColor: colors.accentSoft`, `strokeWidth: 2`, 실선(위 "색상 결정" 절 참고).
- 거리/시간 라벨, 화살표, 방향 표시 없음(REQ-trajectory-line 명시 제약).

### 네비게이션 탭바

- 2탭: "오늘"(`(tabs)/index.tsx`) / "캘린더"(`(tabs)/calendar.tsx`, 플레이스홀더).
- 아이콘 없음, 라벨만 — 시스템 기본 탭바 스타일 유지하되 새 SF Symbol 선택이라는 추가 디자인 결정을 이 phase에서 만들지 않기 위한 보수적 기본값(추후 Phase 6이 햄버거 아이콘과 함께 탭 아이콘도 붙이고 싶다면 추가 비용 낮음 — 지금 아이콘을 넣었다가 나중에 바꾸는 것보다 안전).

### 사진 리사이징 (REQ-photo-resize) — 새 시각 상태 없음

- 사용자에게 보이는 유일한 변화: 리사이징 실패 시 기존 "사진을 추가하지 못했어요" 인라인 문구(Phase 3, `helperText`/`textMuted`, 사진 영역 바로 아래)가 발동하는 원인이 하나 더 늘어난다는 것뿐 — 새 컴포넌트, 새 로딩 상태, 새 모달 없음.
- 리사이징 진행 중 별도 로딩 인디케이터를 추가하지 않는다 — 기존 사진 선택 → 복사 흐름(Phase 3)에 자연스럽게 낀 동기적 단계로 취급, 체감 지연이 문제되면 계획 단계에서 기존 `ActivityIndicator` 패턴 재사용을 검토(신규 시각 언어 발명 아님).

### 온보딩 / 위치 권한 (REQ-onboarding-empty-state) — 신규 UI 없음
